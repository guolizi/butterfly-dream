## 一、v1 当前的概念模型

```
输入（对话/消息）
    ↓
LLM 提取 → 原子事实（flat pool）
    ↓
三维评分（relevance × recency × importance）
    ↓
检索 → top-N 事实
```

**v1 的隐含假设：**
- 记忆 = 一堆原子事实的集合
- 所有事实存在同一个平面空间里
- 提取是单向的：对话 → 事实
- 检索是 query-driven 的：问什么搜什么
- 事实之间只有实体 co_occur 关系

---

## 二、v2 完整层次架构

```
L5: 灵魂层（人物还原）
    ────────────────────────────────────
    目标：还原出"这个人"
    内容：综合的人物理解、核心特质、价值观、人生主线
    构建：从 L2-L4 综合提炼，按需动态构建
    例子："Caroline 是一个从自我接纳走向帮助他人的坚韧女性"
    ↑

L4: 叙事层（故事线）
    ────────────────────────────────────
    内容：有起承转合的故事线
    构建：从 L2 的时间链+因果链+情感轨迹动态构建
    特点：不同 query 角度可构建不同叙事
    例子："Caroline 2023年的成长故事：寻找自我→融入社群→遭遇挫折→新的方向"
    ↑ 抽象管道喂养

L3: 抽象层（管道，非静态存储）
    ────────────────────────────────────
    模式发现：事件池 → 行为模式池 / 情感模式
    知识归纳：事件池 → 静态知识池（abstracts_from）
    信念形成：综合 → 灵魂层素材
    ↑ 关系构建

L2: 关系层
    ────────────────────────────────────
    时间链 · 因果链 · 实体图 · 溯源 · 情感轨迹
    ↑ 事实关联

L1: 池（事实分类管理）
    ────────────────────────────────────
    事件记录池 | 静态知识池 | 行为模式池
    + 情感维度（独立维度，非池）
    ↑ 提取+分类

L0: 工作记忆
    ────────────────────────────────────
    原始对话轮次 + 微事实索引（FTS5 关键词检索）

遗忘机制 ←━━━━━━━━━━━━━━━━━━━━━━━━━━━━→ 贯穿所有层
```

## 三、架构原则

### 3.1 以人为中心的记忆模型

**核心原则：整个记忆系统以人为中心，所有事实都是个体的独立记忆。**

每个人拥有自己独立的记忆库，从 L0 到 L5 各层都是个体的：

```
同一个事件，不同人的独立记忆：

"Caroline 和 Melanie 一起去露营"

Caroline 的记忆库：  "我和 Melanie 一起去露营了，很开心"
Melanie 的记忆库：   "我和 Caroline 去露营了，她拍了很多照片"

→ 两条独立事实，各自视角，各自存储
```

**对各层的影响：**
- L1 池 → 属于某个人
- L2 关系层 → 某个人的因果链、实体图
- L3 抽象层 → 某个人的行为模式
- L4 叙事层 → 某个人的故事
- L5 灵魂层 → 还原某个人

**跨人关系的表达：**
- 不靠"共享事实"，而是靠各自记忆中的实体引用
- Caroline 的事实提到了 Melanie → Caroline 的实体图中有 Melanie
- Melanie 的事实提到了 Caroline → Melanie 的实体图中有 Caroline
- 跨人关系从各自的实体图中自然涌现，不需要全局人物关系图
- 跨人因果链也是各自视角的（各自记忆库里有各自的描述）

**由此简化的设计：**
- 不需要 `fact_persons` 多角色标记（已有 `fact_entities` 足够）
- 不需要权限模型（每个人的库独立，不存在跨人访问）
- 不需要检索时做人物隔离（检索天然只查当前用户的库）
- 不需要全局人物关系图（关系从各自的实体图涌现）

## 四、各层详解

### L0：工作记忆

| 议题 | 决策 |
|------|------|
| **存储内容** | 原始对话轮次 + 微事实索引（关键词→turn_id→snippet，指向原文位置） |
| **微事实提取** | jieba 分词 + 停用词过滤 + 名词性短语规则（纯本地，零 API） |
| **检索方式** | FTS5 关键词匹配（BM25 × 0.7 + 时间衰减 × 0.3） |
| **检索路由** | 默认：先搜工作记忆 → 匹配不足时搜长期记忆。Agent 可显式指定 `memory="working"` / `"longterm"` / `"all"` |
| **清理策略** | 待定（与架构不相关，实现时再定） |

**微事实索引示意：**

```
原始对话轮次表：
┌──────────┬───────┬──────────────────────────────┐
│ turn_id  │ role  │ content                      │
├──────────┼───────┼──────────────────────────────┤
│ 42       │ user  │ "Caroline 喜欢什么活动？"      │
│ 43       │ asst  │ "她喜欢画画和弹钢琴..."        │
└──────────┴───────┴──────────────────────────────┘

微事实索引表：
┌──────────┬──────────┬──────────────────────────┐
│ keyword  │ turn_id  │ snippet                  │
├──────────┼──────────┼──────────────────────────┤
│ Caroline │ 42,43    │ "Caroline 喜欢什么活动"   │
│ 画画     │ 43       │ "她喜欢画画和弹钢琴"      │
│ 钢琴     │ 43       │ "她喜欢画画和弹钢琴"      │
└──────────┴──────────┴──────────────────────────┘
```

### L1：池（事实分类管理）

**划分依据：二维矩阵**

|  | 时间锚定（具体） | 去时间化（稳定） |
|--|---------------|----------------|
| **具体事实** | **事件记录池** | **静态知识池** |
| **行为模式** | （少见，暂不设） | **行为模式池** |

**三个池定义：**

| 池 | 含义 | 评分侧重 | 生命周期 | 上层能力 |
|----|------|---------|---------|---------|
| **事件记录池** | 有时间锚点的具体事件 | recency | 可遗忘/合并 | 事件回溯 |
| **静态知识池** | 去时间化的稳定知识 | importance | 永久保留 | 人物画像、知识问答 |
| **行为模式池** | 从多次事件归纳的条件-行为模式 | relevance+importance | 保留，可更新 | 行为预测 |

**存储方式：** 概念池独立，事实统一存储（`facts` 表，`type` 字段区分池）

**池间关系：多对多映射**
```
多个事件事实 → 联合抽象 → 一个知识/模式事实
一个事件事实 → 不同上下文 → 多个不同角度的抽象
```
映射通过 `fact_relations` 的 `abstracts_from` 关系记录，含 `context` 字段标注抽象角度。

---

### 情感维度（独立维度，非池）

情感作为独立维度，不存储为具体事实，而是存储**结构化的情感轨迹**。

**三个层次：**

```
情感状态节点（时间点 → 情感状态 + 强度）
    ↓ 关联
情感转变（从什么状态到什么状态 + 触发因素）
    ↓ 抽象
情感模式（多次转变中归纳的规律）
```

**数据结构：**

```
emotion_states:
  state_id, person, timestamp, emotion_label, intensity,
  context_fact_id (关联到触发该情感的事实), notes

emotion_transitions:
  transition_id, person, from_state_id, to_state_id,
  transition_type (正向突破/负向冲击/累积升华/韧性恢复/...),
  trigger_fact_ids (触发转变的多个事实),
  pattern_id (可选，关联到已发现的模式)

emotion_patterns:
  pattern_id, person, description,
  confidence, source_transition_ids,
  created_at, updated_at
```

**情感维度与其他模块的关系：**
```
事件记录池 ← 触发 → 情感状态节点
    ↓                      ↓
时间链 ← 关联 → 情感转变 ← 抽象 → 情感模式
    ↓                      ↓
因果链                   行为预测/情感理解
```

---

### L2：关系层

事实之间、实体之间的关系网络：

| 关系类型 | 说明 | 例子 |
|---------|------|------|
| **时间链** | 时序关系 | "A 发生在 B 之前" |
| **因果链** | 因果关系 | "A 导致了 B" |
| **实体图** | co_occur / 隶属 | "Caroline 和 Melanie 是朋友" |
| **溯源** | 来源追踪 | 这条事实来自 session_3 第5轮 |
| **情感轨迹** | 情感状态的演变路径 | 从"被接纳"到"自豪"到"沮丧"到"满足" |

---

### L3：抽象层（管道）

管道式处理，连接 L1→L2→L4→L5：

| 管道 | 输入 | 输出 | 触发 |
|------|------|------|------|
| **模式发现** | 事件池事实 | 行为模式池 / 情感模式 | 定时 + 情绪转折检测 |
| **知识归纳** | 多个事件事实 | 静态知识池（含 abstracts_from 映射） | 定时 |
| **信念形成** | 模式+知识 | 灵魂层素材 | 定时 |

**抽象管道触发机制：双轨触发**

| 触发方式 | 适用场景 | 时机 | 产出 |
|---------|---------|------|------|
| **情绪转折检测** | 情感层面抽象 | 实时，检测到情绪突变时 | 情感洞察 + 映射 |
| **定时抽象** | 知识层面抽象 | 每 N 条新事实 / 每 M 小时 | 模式归纳 + 映射 |

**情绪转折检测：**
- 检测信号：语气突变、重要事件分享、自我披露、长时间沉默后的情感爆发
- 触发后：回顾近期情节 → LLM 分析情绪模式 → 产出情感抽象事实
- 写入 semantic 池 + 通过 `abstracts_from` 映射回源情节

**定时抽象：**
- 扫描未处理的情节事实
- 按实体/主题聚类 → LLM 分析模式 → 产出知识层面抽象事实
- 写入 semantic/procedural 池 + 映射

---

### L4：叙事层（故事线）

按需动态构建，非静态存储：
- 从 L2 的时间链+因果链+情感轨迹构建故事线
- 不同 query 角度可构建不同叙事
- 有起承转合，有情感弧线

例子：
```
"Caroline 2023年的成长故事：
  第一章：寻找自我（5月）→ 参加支持小组，公开演讲
  第二章：融入社群（6-7月）→ 骄傲游行，归属感上升
  第三章：遭遇挫折（7月）→ 徒步冲突，但韧性恢复
  第四章：新的方向（8-10月）→ 从被接纳到给予支持，领养申请"
```

---

### L5：灵魂层（人物还原）

终极目标——还原出"这个人"：
- 综合的人物理解：核心特质、价值观、人生主线
- 从 L2 关系 + L3 信念 + L4 叙事综合提炼
- 按需动态构建
- 让 Agent 真正"理解"一个人，而不仅仅是检索事实

例子：
```
"Caroline 是一个从自我接纳走向帮助他人的坚韧女性。
  她通过社群参与获得力量，在遭遇挫折后能韧性恢复，
  最终从'寻找接纳'转向'给予支持'——领养孩子是她这一转变的体现。"
```

---

### 遗忘机制（贯穿层）

**核心理念：永远保留，只是检索成本不同。** 类比人脑——不是忘了，是检索成本变高了。

遗忘不是删除，而是**冷热分级 + 精度衰减**的组合：

```
冷热分级决定检索优先级：
  🔥 热 → 🌤️ 温 → ❄️ 冷 → 🧊 冰

精度衰减决定存储质量：
  🔥 float32 → 🌤️ float16 → ❄️ int8 → 🧊 1bit
```

各层通过**冷却系数**叠加影响记忆热度，而非争论删不删：
- L1：低 importance → 冷却加速
- L2：高关系密度 → 冷却减速
- L3：已被抽象替代 → 冷却加速
- L4：叙事关键节点 → 冷却减速
- L5：核心特质相关 → 冷却减速

被检索命中时热度回升（+1 级），但精度不恢复——类比人回忆往事，想起来的是模糊版本。完整设计见 §7.7。

| 反馈点 | 决策 |
|--------|------|
| **L4 叙事缓存** | ✅ 采纳。叙事层改为定时构建 + 缓存 + 按需刷新，不每次动态构建 |
| **遗忘 = 精度衰减** | ✅ 采纳。与冷热分级整合：热度等级同时决定检索权重和存储精度（🔥float32→🌤️float16→❄️int8→🧊1bit），永远不删除，精度自然衰减 |
| **睡眠周期调度器** | ✅ 采纳。把所有批量操作（巩固、抽象、遗忘、叙事构建）集中到空闲时段，分阶段执行 |
| **灵魂层作为愿景** | ✅ 保留为设计目标（L5），不作为 v2 的交付组件 |
| **情感维度 context_fact_ids 复数** | ✅ 采纳。改为复数，允许多条事实触发一个情感状态 |
| **情感维度初期一表** | ✅ 采纳。初期只用 `emotion_events`，transitions 和 patterns 查询时动态推导，数据量足够后再物化 |

### 7.3 已确认的设计方向

| 议题 | 决策 |
|------|------|
| **L2 关系层默认实现** | 时间纠缠（时间邻近度作为隐式关系权重），零成本全覆盖 |
| **时间链** | LLM 提取时标注，相对简单可靠 |
| **因果链** | ✅ 已讨论。三层因果构建：短程（时间邻近统计）→ 中程（L3 抽象桥接）→ 长程（L4 叙事补全）；多因一果用 cause_fact_ids 列表 + 辅助索引表 |

### 7.5 二维矩阵空洞 — 行为模式的时间维度（2026-06-13 讨论）

**问题：** 二维矩阵左下角（时间锚定 × 行为模式）为空。行为模式并不总是去时间化的——有些模式天然带有时间窗口，放在纯去时间化的行为模式池里会丢失"模式如何随时间演化"的关键信息。

**决策：行为模式池增加时间维度，统一处理时间锚定和去时间化两种情况。**

```
数据结构：
  pattern_id, person, description,
  status (待验证/验证中/有效/已替代),
  confidence (0.0~1.0),
  valid_from, valid_until,     -- 时间窗口
  evolved_from_pattern_id,     -- 从哪个旧模式演化来的
  source_fact_ids,             -- 支撑这个模式的情节事实
  created_at, updated_at
```

**模式生命周期：从模糊到清晰**

```
[待验证]  →  [验证中]  →  [有效]  →  [已替代]
 conf≥0.3    conf≥0.6    conf≥0.8   新模式有效
```

| 状态 | 含义 | 触发条件 | 检索行为 |
|------|------|---------|---------|
| **待验证** | 刚发现，证据不足 | 抽象管道发现潜在模式（≥3条相似事件） | 不返回，仅内部参考 |
| **验证中** | 有更多证据，但还不够确信 | 匹配事件达到阈值（如≥7条） | 可选返回（带低置信度标注） |
| **有效** | 确认的行为模式 | 置信度 > 阈值（如0.8）+ 时间稳定 | 正常返回 |
| **已替代** | 被新模式取代 | 新模式进入"有效"状态，关联 evolved_from | 仅按需返回（查演化历史时） |

**验证机制：**

```
新事件进入事件记录池
    ↓
检查已有"待验证"模式：这个事件匹配哪个假设？
    ↓ 匹配 → 置信度 +1，source_fact_ids 追加 → 达到阈值 → 状态提升
    ↓ 不匹配 → 检查是否与某个"有效"模式矛盾？
                  ↓ 持续矛盾 → 触发新模式假设（待验证）
                  ↓ 新模式有效 → 旧模式标记为"已替代"
```

**演化链判断（待细化）：** 新模式出现时，需 LLM 判断是"旧模式的演化"还是"独立新模式"。初步方向：同一实体 + 同一主题/维度的模式变更自动视为演化链候选，LLM 做最终确认。

**去时间化模式 = 有效状态 + valid_until=NULL**，即当前仍然成立的模式。一个池覆盖两种场景。

### 7.6 L3 抽象管道的循环依赖问题（2026-06-13 讨论）

**问题：** 抽象管道存在三个循环依赖：
1. 抽象产物被写入 L1 后，可能再次被 L3 当作原材料抽象（无意义循环）
2. L3 需要 L2 的因果链，但因果链需要 L3 的语义理解（鸡生蛋蛋生鸡）
3. 新抽象事实 → 新关系 → 触发新抽象 → 无限循环

**核心洞察：** 抽象可以跨多级继续（类似 LLM 的 autoregressive 生成），关键不是"能不能继续"，而是"什么时候该停"。

#### 循环 ①：抽象产物再被抽象 — 允许，自然收敛

类比 LLM 生成：前面的输出作为后续输入，直到没什么可说的为止。

**终止条件（五重保障）：**

| 终止条件 | 机制 | 说明 |
|---------|------|------|
| **信息增益衰减** | 新产出 < 输入 × 0.3 | 越往上越少，自然收敛 |
| **新颖性检查** | 产出与已有同层事实语义相似度 < 0.85 | 防止"积极参与"→"非常积极参与"废话循环 |
| **置信度门槛递增** | L0→L1: ≥0.6, L1→L2: ≥0.7, L2→L3: ≥0.8 | 越抽象需要越强证据 |
| **LLM 自检** | "原始事件中是否还有未被覆盖的重要模式？" | 模型自己判断 EOS |
| **硬性上限（兜底）** | 最大 3-4 轮，最大 Level 3-4 | 防止极端情况 |

```
执行流程：
  Round 1: 300条事件 → 50条抽象 (level=1) 压缩比6:1 ✅
  Round 2: 50条抽象 → 8条信念 (level=2) 压缩比6:1 ✅
  Round 3: 8条信念 → 1条特质 (level=3) 置信度0.82≥0.8 ✅
  Round 4: 1条特质 → 0条产出 → LLM自检"无新东西" → 🛑 终止
```

#### 循环 ②：L3 需要 L2，L2 需要 L3 — 分两阶段

```
阶段 1（L3 之前）：统计层面 — 不需要语义理解
  时间纠缠：纯时间邻近度，零成本全覆盖
  实体图：co_occur 统计
  时间链：LLM 提取时标注（不依赖 L3）

阶段 2（L3 之后）：语义层面 — 用 L3 的抽象知识精炼
  因果链：时间纠缠候选对 + L3 抽象知识 → LLM 验证
  情感轨迹：L3 情感模式 + 时间链 → 构建
```

**L3 跑之前，L2 已有基础关系可用（时间纠缠 + 时间链），L3 不需要等因果链。**

#### 循环 ③：新事实触发无限循环 — 冷却 + 阈值

```
触发条件（同时满足）：
  1. 距上次抽象 ≥ N 小时（冷却期）
  2. 新增原始事件 ≥ M 条（足够新材料）
  3. 当前处于睡眠周期（不打扰在线服务）

终止条件：
  - 本轮无新产出（信息增益不足）
  - 或 LLM 自检返回"无新东西"
  - 或达到最大迭代轮次
```

**核心原则：L2 的统计层（时间纠缠）是 L3 的前提，L3 的产出是 L2 语义层（因果链）的输入，两者交替迭代而非循环依赖。**

### 7.7 遗忘仲裁 → 冷热分级（2026-06-13 讨论）

**核心洞察：** 存储空间不是瓶颈，核心问题不是"删不删"，而是"好不好查"。类比人脑——不是忘了，是检索成本变高了。

**决策：放弃"删除仲裁"思路，改为冷热分级。所有事实永远保留，只是检索优先级不同。**

#### 热度模型

```
热度 = f(recency, access_frequency, importance, 是否被替代)

🔥 热 → 🌤️ 温 → ❄️ 冷 → 🧊 冰
```

| 级别 | 触发条件 | 检索行为 | 权重 | 精度 | 类比 |
|------|---------|---------|------|------|------|
| 🔥 **热** | 最近 N 天提取 / 高频访问 | 默认参与检索 | × 1.0 | float32 | "脱口而出" |
| 🌤️ **温** | 超过 N 天未访问 / 中频 | 默认参与检索 | × 0.7 | float16 | "想一下能想起来" |
| ❄️ **冷** | 被抽象替代 / 长期未访问 | 需 `memory="deep"` | × 0.4 | int8 | "努力回忆" |
| 🧊 **冰** | 深度归档 / 仅历史价值 | 需 `memory="all"` | × 0.2 | 1bit | "需要线索才能想起" |

#### 冷却与加热

```
冷却规则：
  新事实 → 🔥 热
      ↓ 超过 7 天未访问
  🌤️ 温
      ↓ 超过 30 天未访问 或 被 L3 抽象替代
  ❄️ 冷
      ↓ 超过 90 天 且 无叙事关键标记
  🧊 冰（但永远不删）

加热规则：
  被检索命中 → 热度 +1 级
  被 L4 标记为叙事关键节点 → 永久保持温以上
  被 L5 标记为核心特质相关 → 永久保持温以上
```

#### 各层不再打架，而是叠加影响冷却速度

```
L1 池：低 importance → 冷却加速 × 1.5
L2 关系层：高关系密度 → 冷却减速 × 0.5
L3 抽象层：已被抽象替代 → 冷却加速 × 2.0
L4 叙事层：叙事关键节点 → 冷却减速 × 0.3
L5 灵魂层：核心特质相关 → 冷却减速 × 0.3

综合冷却系数 = 各层系数相乘
```

**例子：**
```
事实: "Caroline 2023-05-08 参加了支持小组"
  L1: importance=3 → 加速 × 1.5
  L2: 12条关系链 → 减速 × 0.5
  L3: 已抽象替代 → 加速 × 2.0
  L4: 叙事关键节点 → 减速 × 0.3
  ────────────────────────────
  综合: 1.5 × 0.5 × 2.0 × 0.3 = 0.45
  → 冷却很慢，长期保持温/热 ✅
```

#### 检索路由

```
默认检索 (memory="auto"):  🔥 热 + 🌤️ 温
深度检索 (memory="deep"):  🔥 + 🌤️ + ❄️ 冷
考古检索 (memory="all"):   全部包括 🧊 冰
```

**对比传统遗忘仲裁：**

| | 遗忘仲裁 | 冷热分级 |
|--|---------|---------|
| 核心理念 | 删不删 | 好不好查 |
| 各层关系 | 冲突 → 仲裁 | 叠加 → 冷却系数 |
| 出错风险 | 高（误删不可逆） | 低（只是难查，还在） |
| 实现复杂度 | 高（仲裁逻辑） | 低（冷却公式） |
| 存储 | 需要清理 | 永远保留 |
| 类比 | 文件系统 | 人脑记忆 |

### 7.8 因果链构建 — 三层方案（2026-06-13 讨论）

**核心问题：** 时间邻近只能抓短程因果，长期因果链一断，L4 叙事层就建不起来。

**决策：三层因果构建，从短程到长程逐层打通。**

```
短程（时间邻近，几天）──→ 统计发现，事件级
    ↓
中程（主题关联，月级）──→ L3 抽象桥接，主题级
    ↓
长程（叙事补全，年级）──→ L4 叙事构建，故事级
```

#### Layer 1：短程因果（事件级，已有方案）

```
时间纠缠权重 > 阈值 → 候选对
    → 多信号评分（时间邻近度/共现频率/时序一致性/语义相关/实体重叠/情感变化）
    → 高分直接确认，中分送 LLM 验证，低分丢弃
```

#### Layer 2：中程因果（L3 抽象桥接）

用 L3 抽象事实作为"桥接节点"连接被时间鸿沟隔开的事件：

```
原始事件（分散在时间轴）：
  5月: 参加支持小组
  6月: 公开演讲
  7月: 参加骄傲游行
  8月: 做志愿者
  10月: 决定做心理咨询师

L3 抽象（桥接节点）：
  "Caroline 通过社群参与获得自我认同"（覆盖 5-7 月）
  "Caroline 从被帮助者转变为帮助者"（覆盖 8-10 月）

因果链通过抽象节点连接：
  参加支持小组 → [自我认同提升] → 公开演讲 → [社群归属感] → 骄傲游行
  → [身份转变] → 做志愿者 → [帮助他人获得意义] → 决定做心理咨询师
```

**实现：** 睡眠周期中，对每个 L3 抽象事实找到它 abstracts_from 的原始事件，按时间排序，LLM 判断事件间隐含因果逻辑。

#### Layer 3：长程因果（L4 叙事补全）

叙事构建时发现因果链缺口，用 LLM 生成假设因果路径，再用冷记忆验证：

```
已有：5月参加支持小组 → ... → 10月决定做心理咨询师（中间断裂）
L4 触发 LLM："基于 Caroline 的行为模式和价值观，5-10月最可能的因果路径？"
    → LLM 生成假设链（标记为 inferred）
    → 检索冷记忆验证/修正
```

#### 数据模型（多因一果支持）

```sql
-- 主表：因果组（多因一果用列表存储）
causal_relations:
  relation_id,
  effect_fact_id,          -- 结果
  cause_fact_ids,          -- 原因列表 [1, 2, 3]（JSON 数组）
  causality_type,          -- direct(短程) / indirect(中程) / inferred(长程)
  confidence,
  layer,                   -- 1 / 2 / 3
  abstracted_by,           -- 中程关联的 L3 抽象事实 ID
  signals_json,
  validated_by,            -- statistical / llm
  created_at

-- 辅助索引表：加速反向查询（"这个事件导致了什么"）
causal_relation_members:
  relation_id, cause_fact_id
  -- 联合索引 (cause_fact_id, relation_id)
```

写入时自动展开 cause_fact_ids 到辅助表，查询时走索引。
