# 🦋 Butterfly Dream v2 — 顶层架构设计讨论

> 参与者：guolizi（主人）、Neko-chan

---

## 一、v1 当前的概念模型

```
输入（对话/消息）
    ↓
LLM 提取 → 原子事实（flat pool）
    ↓
三维评分（relevance × recency × importance）
    ↓
检索 → top-N 事实
```

**v1 的隐含假设：**
- 记忆 = 一堆原子事实的集合
- 所有事实存在同一个平面空间里
- 提取是单向的：对话 → 事实
- 检索是 query-driven 的：问什么搜什么
- 事实之间只有实体 co_occur 关系

---

## 二、v2 完整层次架构

```
L5: 灵魂层（人格建模 + 行为预测）
    ────────────────────────────────────
    目标：预测"这个人接下来会做什么"
    内容：人格模型（核心价值观/情绪调节/决策倾向/关系模式/人生阶段）
    构建：从 L2-L4 综合提炼，分阶段交付（Phase1 叙事摘要 → Phase2 预测引擎）
    关键：L5 的预测是矛盾检测的核心基准线
    ↑

L4: 叙事层（故事线 — 人生主干）
    ────────────────────────────────────
    内容：有起承转合的人生主线（持久化）+ 细节叙事（按需构建）
    构建：持久化主干从 L2+L3 定时提炼，动态细节基于主干+query 按需构建
    特点：L5 的外在表现，两者双向验证
    例子："Caroline 的成长故事：寻找自我→融入社群→遭遇挫折→新的方向"
    ↑ 抽象管道喂养

L3: 抽象层（管道 — 输入输出均持久化在 L1）
    ────────────────────────────────────
    模式发现：事件池 → 行为模式池 / 情感模式
    知识归纳：事件池 → 静态知识池（abstracts_from）
    ↑ 关系构建

L2: 关系层
    ────────────────────────────────────
    时间链 · 因果链 · 实体图 · 溯源 · 情感轨迹
    ↑ 事实关联

L1: 池（事实分类管理）
    ────────────────────────────────────
    事件记录池 | 静态知识池 | 行为模式池
    + 情感事件池（第 4 个池，独立维度）
    ↑ 提取+分类

L0: 工作记忆
    ────────────────────────────────────
    原始对话轮次 + 微事实索引（FTS5 关键词检索）

遗忘机制 ←━━━━━━━━━━━━━━━━━━━━━━━━━━━━→ 贯穿所有层
```

## 三、架构原则

### 3.1 记忆主体模型：agent 的认知层

**核心原则：Butterfly Dream 是 agent 的认知层，记录 agent 从对话中观察到和学习到的一切。** 所有对话参与者（包括 agent 自身）都是平等的被观察对象。

```
          agent（主体，记忆的拥有者）
         ┌──────────────────────────────┐
         │   🧠 Butterfly Dream         │
         │   (agent 的认知层)            │
         │                              │
         │   person=Caroline 的事实      │
         │   person=Mel 的事实           │
         │   person=Neko-chan 的事实     │
         │   person=主人 的事实           │
         │   ...                        │
         └──────────────────────────────┘
                  ↑ 观察
         ┌──────────────────┐
         │   对话中的世界     │
         │ Caroline ↔ Mel   │
         │ 主人 ↔ Neko-chan  │
         └──────────────────┘
```

**对 L0 的影响：**
- `person` = 实际说话人（Caroline、Mel、Neko-chan、主人……）
- 不需要 `role` 字段——`person` 已经表达了谁说了什么，系统架构标签（user/assistant）对记忆内容无意义
- 系统消息（prompt 指令）不进入记忆系统，L0 提取时直接过滤

**对 L1-L5 的影响：**
- 所有参与者都拥有独立的记忆轨迹，从 L1 到 L5 各层都是按 `person` 分组的
- agent 自身也有 L1-L5：L5 人格模型就是 agent 的**自我认知模型**

```
同一个对话，不同人的独立记忆：

"Caroline 和 Melanie 一起去露营"

Caroline 的记忆： "我和 Melanie 一起去露营了，很开心"
Melanie 的记忆：  "我和 Caroline 去露营了，她拍了很多照片"
Neko-chan 的记忆："主人和 Caroline 聊到露营，主人似乎也很想去"
→ 三条独立事实，各自视角，各自存储
```

**跨人关系的表达：**
- 不靠"共享事实"，而是靠各自记忆中的实体引用
- Caroline 的事实提到了 Melanie → Caroline 的实体图中有 Melanie
- Melanie 的事实提到了 Caroline → Melanie 的实体图中有 Caroline
- 跨人关系从各自的实体图中自然涌现，不需要全局人物关系图

**由此简化的设计：**
- 不需要 `fact_persons` 多角色标记（已有 `fact_entities` 足够）
- 不需要权限模型（每个人的库独立，不存在跨人访问）
- 不需要检索时做人物隔离（检索天然只查当前用户的库）
- 不需要全局人物关系图（关系从各自的实体图涌现）

### 3.2 冷启动策略：渐进激活

**核心原则：上层不设硬开关，数据量达到阈值后自动激活。** 每个阶段都有交付价值，用户不会感到"系统坏了"。

各层的数据依赖链决定了它们无法同时激活——L0+L1 立即可用，L2-L5 需要数据积累后渐进涌现。

```
数据量（对话轮次）
    ↑
500+ ─── L5 Phase 2（预测引擎）
    │     需要：足够的行为模式 + 历史预测验证
    │
200+ ─── L5 Phase 1（人格摘要）
    │     需要：多个叙事 → 提炼核心特质
    │
100+ ─── L4 叙事层
    │     需要：跨时间跨度的事件 + 因果链
    │
 50+ ─── L3 抽象管道
    │     需要：≥3条相似事件 → 发现模式
    │
 10+ ─── L2 时间链 + 实体图
    │     需要：多条事实 → 建立时间关系和共现
    │
  1+ ─── L0 + L1（立即可用）
         LLM 提取事实 → 写入三池
         FTS5 关键词索引 → 可检索
```

**各层渐进激活条件：**

| 层 | 激活条件 | 之前的状态 | 激活后的新能力 |
|:--:|:--------:|:----------:|:--------------:|
| L2 关系层 | ≥ 10 条事实 | 只有 L0+L1 检索 | 事实间有时间顺序和共现关系 |
| L3 抽象管道 | ≥ 50 条事件，同一主题 ≥ 3 次 | L2 统计层 | 发现行为模式、归纳知识 |
| L4 叙事层 | ≥ 100 条事件，覆盖 ≥ 2 个时间跨度 | L3 模式 + L2 关系 | 构建有起承转合的故事线 |
| L5 Phase 1 | ≥ 200 条事件，L4 主干 ≥ 3 个时间跨度 | 各层独立 | 提炼人物核心特质 |
| L5 Phase 2 | Phase 1 稳定 + 有效模式 ≥ 5 个 | 只能回顾过去 | 预测未来行为 |

**渐进激活的好处：**
- 用户不会感到"系统坏了"——即使只有 L0+L1，检索也能工作
- 每个阶段都有交付价值，不是等到"全部就绪"才可用
- 自然形成数据质量门槛——数据不够时强行激活上层只会产出低质量结果

**特殊情况：导入历史数据**

如果用户导入历史聊天记录，数据量可能直接达到 1000+，L2-L5 可以跳过渐进激活直接进入完整状态。但历史数据的置信度应低于实时数据：标记为 `source=historical_import`，置信度打 0.7 折。

## 四、各层详解

### L0：工作记忆

| 议题 | 决策 |
|------|------|
| **存储内容** | 原始对话轮次 + 微事实索引（关键词→turn_id→snippet，指向原文位置） |
| **微事实提取** | jieba 分词 + 停用词过滤 + 名词性短语规则（纯本地，零 API） |
| **检索方式** | FTS5 关键词匹配 + 可选 embedding（🔥/🌤️ 时），排序公式：`BM25 × 0.5 + 时间衰减 × 0.3 + query_embed_sim × 0.2`（详见检索设计文档 §3.2） |
| **检索路由** | 由 QueryClassifier 自动路由（详见 §7 检索路由设计），不再使用 `memory` 参数机制 |
| **晋升机制** | 双通道晋升：热晋升（查询驱动，仅标记不执行）+ 冷晋升（睡眠周期，批量提取）。详见 §4-L0 晋升机制 |
| **清理策略** | 待定（与架构不相关，实现时再定） |

**微事实索引示意：**

```
原始对话轮次表：
┌──────────┬──────────┬──────────────────────────────┐
│ turn_id  │ person   │ content                      │
├──────────┼──────────┼──────────────────────────────┤
│ 42       │ 主人     │ "Caroline 喜欢什么活动？"      │
│ 43       │ Neko-chan│ "她喜欢画画和弹钢琴..."        │
└──────────┴──────────┴──────────────────────────────┘

微事实索引表：
┌──────────┬──────────┬──────────────────────────┐

├──────────┼──────────┼──────────────────────────┤
```

#### L0→L1 晋升机制

L0 的微事实索引是纯本地的关键词索引，而 L1 的结构化事实需要 LLM 提取。为了让 L0 中发现的有价值信息进入 L1，采用**双通道晋升**——热晋升只收集信号，冷晋升统一执行。

```
热晋升（查询驱动）        冷晋升（睡眠周期）
┌──────────────┐        ┌──────────────────┐
│ 用户搜"画画"   │        │ 扫描 L0 微事实索引 │
│ L0 命中 ✓    │        │ + 热晋升标记队列   │
│ L1 未命中 ✗  │        │ 合并处理          │
│ 标记 +1       │        │ 多维度LLM提取     │
│ 存到队列      │        │ 按维度分发写入L1   │
└──────┬───────┘        └────────┬─────────┘
       │                         ↑
       └────── 合并 ─────────────┘
```

**热晋升（查询驱动，仅标记不执行）：**
- 用户搜索 → L0+L1 同时检索
- L0 命中某个关键词，L1 没有对应事实 → 该关键词的"缺失计数" +1
- 缺失计数 ≥ 3 → 加入晋升标记队列（不触发 LLM，不打断查询）
- 队列信息：关键词、关联的原始对话轮次、缺失计数

**冷晋升（睡眠周期，批量执行）：**
- 睡眠周期中，合并处理：
  - 热晋升标记队列（缺失计数 ≥ 3 的关键词）
  - L0 高频关键词簇（同一主题出现 ≥ 5 条对话）
- 每个关键词簇 → 关联的原始对话轮次 → LLM **多维度提取**
- 各维度结果分发写入 L1 对应池/维度
- L0 微事实保留（作为溯源锚点），晋升后 L0 搜索权重微降

#### 多维度提取

单次 LLM 提取容易遗漏某些维度的信息（如只提取了事件，漏了情感和关系）。因此晋升时采用**一次 LLM 调用，多维度输出**：

```
LLM Prompt 示意：

"从以下对话中，分别从这些维度提取信息：
1. 事件（时间+地点+人物+动作）
2. 情感（谁的情感状态+强度）
3. 关系（人物之间的关系）
4. 属性（人物的稳定特征/偏好）
5. 行为模式（条件-行为规律）

对话内容：
[原始对话轮次]

请按 JSON 格式输出各维度的提取结果。"
```

**五个提取维度：**

| 维度 | 说明 | 写入目标 | 例子 |
|------|------|---------|------|
| **事件** | 有时间锚点的具体事件 | 事件记录池 | "Caroline 和 Melanie 昨天去露营了" |
| **情感** | 情感状态 + 强度 | 情感维度 (emotion_events) | "Caroline 很开心" (intensity=0.8) |
| **关系** | 人物之间的关系 | L2 实体图 | "Caroline 和 Melanie 是朋友" |
| **属性** | 人物的稳定特征/偏好 | 静态知识池 | "Caroline 喜欢户外活动" |
| **行为模式** | 条件-行为规律 | 行为模式池（待验证） | "Caroline 天气不好时也能保持积极" |

**整合与去重规则：**

```
事件 → 事件记录池（新事实，与已有同实体+同内容合并）
情感 → emotion_events（新情感节点）
关系 → 实体图更新（已有则强化置信度，没有则新建）
属性 → 静态知识池（与已有去重：同实体+同属性名→合并）
模式 → 行为模式池（待验证，与已有去重）
```

**晋升流程（完整版）：**

```
冷晋升触发
    ↓
关键词簇 → 关联的原始对话轮次
    ↓
LLM 多维度提取（一次调用，多维度 JSON 输出）
    ↓
解析结果 → 按维度分发
    ↓
┌──────┬──────┬──────┬──────┬──────┐
│ 事件  │ 情感  │ 关系  │ 属性  │ 模式  │
│记录池 │维度   │实体图 │知识池 │模式池 │
└──────┴──────┴──────┴──────┴──────┘
    ↓
各池去重整合
    ↓
L0 微事实权重微降
```

**晋升时的池分类规则：**

| 原始对话内容 | 写入 L1 的池 | 例子 |
|-------------|-------------|------|
| 有时间锚点 + 单次事件 | 事件记录池 | "昨天画了画" |
| 无时间锚点 + 稳定属性 | 静态知识池 | "喜欢蓝色" |
| 无时间锚点 + 条件性行为 | 静态知识池（自述行为倾向） | "压力大时会画画" |
| **有时间锚点 + 周期性/条件性** | **行为模式池（自述模式，待验证）** | **"每周日都去游泳"** |

**行为模式池的双通道输入：**

```
来源 A: L3 抽象管道（跨事件统计发现）
  confidence=0.6 → 验证中
  source_fact_ids = [事件1, 事件2, 事件3]

来源 B: L0→L1 晋升（用户自述模式）
  confidence=0.3 → 待验证
  source=self_report
  source_fact_ids = [原始对话轮次]

两者走同一个生命周期：
  待验证 → 验证中 → 有效 → 已替代

L3 会持续验证自述模式：
  - 匹配到实际事件 → confidence ↑
  - 被实际事件否定 → 标记不一致
```

#### 热路径晋升（高重要性即时触发）

上述双通道晋升（热标记+冷批量）适用于大多数事实，但某些高重要性事实需要**即时处理**不等睡眠周期：

| 触发条件 | 处理方式 | 例子 |
|:--------|:--------|:-----|
| LLM 提取时检测到 `importance ≥ 0.9` | 立即写入 L1，触发 L2 关系增量更新 | "我恨你"、"我们结婚吧" |
| 情感强度 `intensity ≥ 0.9` | 立即写入情感维度，触发情绪转折检测 | 极端情绪爆发 |
| 用户明确要求"记住这个" | 立即写入静态知识池，标记为 `pinned` | "记住我讨厌香菜" |

**实现方式：** 在 LLM 多维度提取的返回格式中增加 `importance` 字段，冷晋升时同步判断。热路径晋升后 L0 微事实权重直接降为 0（已确认晋升），不等睡眠周期衰减。

```
冷晋升（睡眠周期，批量）    热路径（即时，高重要性）
┌──────────────────┐       ┌──────────────────┐
│ 扫描 L0 微事实    │       │ LLM 提取时检测    │
│ + 热晋升标记队列  │       │ importance ≥ 0.9  │
│ 合并处理          │       │ 立即写入 L1       │
│ 多维度LLM提取     │       │ 触发 L2 增量更新  │
│ 按维度分发写入L1  │       │ L0 权重直接归零   │
└──────────────────┘       └──────────────────┘
```

### L1：池（事实分类管理）

**划分依据：二维矩阵**

|  | 时间锚定（具体） | 去时间化（稳定） |
|--|---------------|----------------|
| **具体事实** | **事件记录池** | **静态知识池** |
| **行为模式** | **行为模式池**（带时间维度 valid_from/valid_until） | **行为模式池**（valid_until=NULL = 当前有效） |

**三个池定义：**

| 池 | 含义 | 评分侧重 | 生命周期 | 上层能力 |
|----|------|---------|---------|---------|
| **事件记录池** | 有时间锚点的具体事件 | recency | 冷热分级（永远保留） | 事件回溯 |
| **静态知识池** | 去时间化的稳定知识 | importance | 永久保留 | 人物画像、知识问答 |
| **行为模式池** | 从多次事件归纳的条件-行为模式，也接受 L0→L1 晋升的自述模式（待验证） | relevance+importance | 保留，可更新 | 行为预测 |

**存储方式：** 概念池独立，事实统一存储（`facts` 表，`type` 字段区分池）

**池间关系：多对多映射**
```
多个事件事实 → 联合抽象 → 一个知识/模式事实
一个事件事实 → 不同上下文 → 多个不同角度的抽象
```
映射通过 `fact_relations` 的 `abstracts_from` 关系记录，含 `context` 字段标注抽象角度。

**结构化事件字段（增强版）：**

L0→L1 晋升时，LLM 提取事件维度时**尽量**填充结构化字段，但不强制——复杂事件（如"他因为被拒绝而伤心地离开了"）保留自由文本比强行拆结构更有价值。

```json
{
  "text": "Caroline 在 2024 年 3 月报名了产品经理课程",
  "structured": {
    "subject": "Caroline",
    "action": "报名",
    "object": "产品经理课程",
    "time": "2024-03",
    "location": null
  },
  "entities": ["Caroline", "产品经理课程"],
  "category": "event"
}
```

| 字段 | 说明 | 填充策略 |
|:----|:----|:--------|
| `subject` | 行为主体 | LLM 尽量提取，缺失不阻塞 |
| `action` | 行为动作 | 标准化同义词（"报名"vs"注册"→统一），但不强制 |
| `object` | 行为对象/目标 | 可为空（如"Caroline 在发呆"） |
| `time` | 时间锚点 | 尽量标准化为 ISO 格式，模糊时间保留原文 |
| `location` | 地点 | 经常缺失，不强制 |

结构化字段的主要消费者是**符号规则引擎**（见下文 L2 因果链构建），非强制填充保证了长尾复杂事件不被截断。

#### 行为模式池的时间维度

**问题：** 二维矩阵左下角（时间锚定 × 行为模式）为空。行为模式并不总是去时间化的——有些模式天然带有时间窗口，放在纯去时间化的行为模式池里会丢失"模式如何随时间演化"的关键信息。

**决策：行为模式池增加时间维度，统一处理时间锚定和去时间化两种情况。**

```
数据结构：
  pattern_id, person, description,
  status (待验证/验证中/有效/已替代),
  confidence (0.0~1.0),
  valid_from, valid_until,     -- 时间窗口
  evolved_from_pattern_id,     -- 从哪个旧模式演化来的
  source_fact_ids,             -- 支撑这个模式的情节事实
  created_at, updated_at
```

**模式生命周期：从模糊到清晰**

```
[待验证]  →  [验证中]  →  [有效]  →  [已替代]
 conf≥0.3    conf≥0.6    conf≥0.8   新模式有效
```

| 状态 | 含义 | 触发条件 | 检索行为 |
|------|------|---------|---------|
| **待验证** | 刚发现，证据不足 | 抽象管道发现潜在模式（≥3条相似事件） | 默认不返回，仅内部参考 |
| **验证中** | 有更多证据，但还不够确信 | 匹配事件达到阈值（如≥7条） | 默认不返回，`memory=deep` 时可选返回（带低置信度标注） |
| **有效** | 确认的行为模式 | 置信度 > 阈值（如0.8）+ 时间稳定 | 正常返回 |
| **已替代** | 被新模式取代 | 新模式进入"有效"状态，关联 evolved_from | 仅按需返回（查演化历史时） |

**验证机制：**

```
新事件进入事件记录池
    ↓
检查已有"待验证"模式：这个事件匹配哪个假设？
    ↓ 匹配 → 置信度 +1，source_fact_ids 追加 → 达到阈值 → 状态提升
    ↓ 不匹配 → 检查是否与某个"有效"模式矛盾？
                  ↓ 持续矛盾 → 触发新模式假设（待验证）
                  ↓ 新模式有效 → 旧模式标记为"已替代"
```

**演化链判断：** 新模式出现时，需判断是"旧模式的演化"还是"独立新模式"。初步方向：同一实体 + 同一主题/维度的模式变更自动视为演化链候选，LLM 做最终确认。

注：演化链本质上是时间链（记录变化顺序）+ 因果链（解释变化原因）的特例。行为模式池的 `evolved_from` 是显式记录模式间演化关系的便利字段，而非独立机制。事件记录池和静态知识池不需要单独的演化链——时间戳 + 矛盾检测的 `contradicted_by` 已覆盖版本追踪需求。

**去时间化模式 = 有效状态 + valid_until=NULL**，即当前仍然成立的模式。一个池覆盖两种场景。

### 情感事件池（L1 第 4 个池）

情感事件作为 L1 的第 4 个池，与事件记录池、静态知识池、行为模式池并列。详见独立设计文档 `docs/v2-emotion-dimension.md`。

情感池存储**结构化的 VAD 序列**，与事件池通过 `primary_fact_id` 关联——情感池是连续的线，事件池是线上的点。

**核心定位：** 信号层，不是推理层。记录"发生了什么情感"，不负责"为什么"和"接下来会怎样"。

**四大核心能力：**
| # | 能力 | 说明 |
|:-|:----|:-----|
| ❶ | 情感记录（溯源） | 谁在什么时间因为什么事产生了什么情感 |
| ❷ | 情感模式发现（抽象） | 从多次转变中归纳情感反应规律 |
| ❸ | 情感状态感知（实时） | 当前对话中的情感状态 → mood_resonance / psych_probe |
| ❹ | LLM 情感记忆服务 | 让 LLM 能记住用户的重要情感事件、知道什么话题不该碰 |

**关键设计决策：**
- **VAD 三维**替代单标签+强度，LLM 直接输出 VAD 值
- **emotion_model** 字段标记情感模型类型（当前 'vad-3d'），预留未来切换更精细模型的能力
- **emotion_vector JSON** 通用情感向量，唯一主存储（固定字段为 GENERATED 派生列），Phase 3 切换模型时 INSERT 无需修改
- **importance** 字段区分 intensity（多强烈）和 importance（多重要），采用幂律动态衰减（详见 `docs/v2-emotion-dimension.md` §5.3）
- **emotion_triggers** 表记录人物对话题/实体的当前情感状态（话题→VAD 映射），作为人物画像的一部分
- 情感事件支持**多事实关联**（`primary_fact_id` + `related_fact_ids`）
- 事件池新增 **emotion_tag** 轻量标签，供 L3 抽象层直接过滤，无需每次 JOIN 情感池
- 初期一表（emotion_events），Phase 2 物化三表 + triggers

**与各层的关系：**
```
事件记录池 ← 触发（primary_fact_id）→ 情感事件池
    ↓                                  ↓
时间链 ← 关联 → 情感转变 ← 抽象 → 情感模式
    ↓                                  ↓
因果链              行为预测 / 情感理解 / LLM 对话
```

### L2：关系层

事实之间、实体之间的关系网络：

| 关系类型 | 说明 | 例子 |
|---------|------|------|
| **时间链** | 时序关系 | "A 发生在 B 之前" |
| **因果链** | 因果关系 | "A 导致了 B" |
| **实体图** | co_occur / 隶属 | "Caroline 和 Melanie 是朋友" |
| **溯源** | 来源追踪 | 这条事实来自 session_3 第5轮 |
| **情感轨迹** | 情感状态的演变路径 | 从"被接纳"到"自豪"到"沮丧"到"满足" |

#### 因果链构建 — 四层方案（2026-06-13 讨论，2026-06-15 扩展）

**核心问题：** 时间邻近只能抓短程因果，长期因果链一断，L4 叙事层就建不起来。

**决策：四层因果推理，从低成本到高成本逐层递进。**

```
Layer 0：符号规则（纯 SQL，零成本）──→ 规则匹配，事件级
    ↓
Layer 1：短程（时间邻近，几天）──→ 统计发现，事件级
    ↓
Layer 2：中程（主题关联，月级）──→ L3 抽象桥接，主题级
    ↓
Layer 3：长程（叙事补全，年级）──→ L4 叙事构建，故事级
```

##### Layer 0：符号规则引擎

**核心问题：** 现有三层因果构建依赖 LLM 语义判断（中程/长程），LLM 有幻觉风险，且短程统计层无法发现跨时间跨度的显式因果。

**决策：在现有三层基础上，新增符号规则层作为第一层，形成四层递进因果推理。**

```
四层因果推理（从低成本到高成本）：

第一层：符号规则引擎（新增，零成本高精度）
  规则匹配 → 自动建立因果候选
  无需 LLM，纯符号逻辑

第二层：短程统计（已有）
  时间邻近 + 共现实体 → 统计相关性

第三层：中程 LLM（已有，扩展）
  L3 抽象桥接 → 语义因果判断

第四层：长程叙事（已有）
  L4 叙事补全 → 跨时间跨度因果
```

**5 条符号规则：**

| 规则 | 描述 | 依赖的结构化字段 | 置信度 | FTS5 兜底 |
|:----|:----|:--------------|:-----:|:--------:|
| **R1 同一主体连续动作** | 同一 subject 在时间窗口内连续动作 | `subject` + `time` | 0.7 | ❌ 消歧风险高 |
| **R2 对象→主体传递** | A 的 object 成为 B 的 subject | `object(A)` + `subject(B)` | 0.6 | ❌ 消歧风险高 |
| **R3 同一主题链** | 同一主题标签的连续事件 | `subject` + 主题标签 | 0.65 | ❌ 消歧风险高 |
| **R4 Action 逻辑序列** | 预定义 action 序列（如"吵架"→"道歉"） | `action`（匹配预定义表） | 0.75 | ✅ 自由文本 FTS5 匹配 |
| **R5 Location 转移** | 地点变化可能隐含因果 | `location` | 0.55 | ✅ 自由文本 FTS5 匹配 |

**FTS5 兜底：** 结构化字段为"尽量填充但不强制"，复杂事件可能缺字段导致规则匹配不上。R4/R5 启用 FTS5 兜底——当结构化字段缺失时，fallback 到 L0 微事实索引（FTS5）在自由文本中搜索规则关键词。仅 R4/R5 启用 FTS5 兜底，因为 action 和 location 在自由文本中消歧风险低（"吵架"就是吵架，"北京"就是北京），而 subject 和主题标签的 FTS5 消歧风险高（"他"、"她"等代词）。FTS5 匹配结果的置信度降一级处理（如 R4 从 0.75 降至 0.6）。

**规则引擎输出：**

| 匹配数 | 置信度 | 处理方式 | 说明 |
|:-----:|:-----:|:--------|:----|
| ≥ 3 条规则匹配 | 0.95 | 直接入库，置信度取均值 | 多规则交叉验证，高可靠 |
| 2 条规则匹配 | 0.80 | 直接入库，标记为 `validated_by: rule` | 中等可靠，无需 LLM 验证 |
| 1 条规则匹配 | 0.60 | 入库但标记 `status: pending_llm_verify`，睡眠周期中 LLM 验证 | 需语义验证 |
| 0 条规则匹配 | — | 走原有三层因果构建 | — |

##### 符号规则 vs LLM 的互补关系

| 方面 | 符号规则（Layer 0） | LLM 语义判断（Layer 2-3） |
|:----|:-----------------|:-----------------------|
| **幻觉风险** | ✅ 零幻觉 | ⚠️ 可能幻觉 |
| **召回率** | ❌ 只能发现显式因果 | ✅ 可发现隐式因果 |
| **精度** | ✅ 极高（规则确定） | ⚠️ 中 |
| **成本** | ✅ 零成本 | ❌ LLM 调用 |
| **适用范围** | 短程、显式、结构化事件 | 长程、隐式、复杂因果 |

**冲突处理：**

```
符号规则说"有因果" + LLM 说"无因果"
  → 以符号规则为准（零幻觉），降低 LLM 置信度

符号规则说"无因果" + LLM 说"有因果"
  → 保留 LLM 结果，但降低置信度（标记为 validated_by: llm_only）
```

##### Layer 1：短程因果（事件级）

```
时间纠缠权重 > 阈值 → 候选对
    → 多信号评分（时间邻近度/共现频率/时序一致性/语义相关/实体重叠/情感变化）
    → 高分直接确认，中分送 LLM 验证，低分丢弃
```

##### Layer 2：中程因果（L3 抽象桥接）

用 L3 抽象事实作为"桥接节点"连接被时间鸿沟隔开的事件：

```
原始事件（分散在时间轴）：
  5月: 参加支持小组
  6月: 公开演讲
  7月: 参加骄傲游行
  8月: 做志愿者
  10月: 决定做心理咨询师

L3 抽象（桥接节点）：
  "Caroline 通过社群参与获得自我认同"（覆盖 5-7 月）
  "Caroline 从被帮助者转变为帮助者"（覆盖 8-10 月）

因果链通过抽象节点连接：
  参加支持小组 → [自我认同提升] → 公开演讲 → [社群归属感] → 骄傲游行
  → [身份转变] → 做志愿者 → [帮助他人获得意义] → 决定做心理咨询师
```

**实现：** 睡眠周期中，对每个 L3 抽象事实找到它 abstracts_from 的原始事件，按时间排序，LLM 判断事件间隐含因果逻辑。

##### Layer 3：长程因果（L4 叙事补全）

叙事构建时发现因果链缺口，用 LLM 生成假设因果路径，再用冷记忆验证：

```
已有：5月参加支持小组 → ... → 10月决定做心理咨询师（中间断裂）
L4 触发 LLM："基于 Caroline 的行为模式和价值观，5-10月最可能的因果路径？"
    → LLM 生成假设链（标记为 inferred）
    → 检索冷记忆验证/修正
```

##### 数据模型（多因一果支持）

```sql
-- 主表：因果组（多因一果用列表存储）
causal_relations:
  relation_id,
  effect_fact_id,          -- 结果
  cause_fact_ids,          -- 原因列表 [1, 2, 3]（JSON 数组）
  causality_type,          -- direct(短程) / indirect(中程) / inferred(长程) / rule(符号规则)
  confidence,
  layer,                   -- 0(符号规则) / 1(短程) / 2(中程) / 3(长程)
  abstracted_by,           -- 中程关联的 L3 抽象事实 ID
  signals_json,
  validated_by,            -- statistical / llm / rule / llm_only
  created_at,
  rule_match_count,        -- 符号规则匹配数（Layer 0 专用）
  rule_ids                 -- 匹配的规则 ID 列表（如 ["R1", "R3"]）

-- 辅助索引表：加速反向查询（"这个事件导致了什么"）
causal_relation_members:
  relation_id, cause_fact_id
  -- 联合索引 (cause_fact_id, relation_id)
```

写入时自动展开 cause_fact_ids 到辅助表，查询时走索引。

**因果链构建在睡眠周期中的位置：**

```
├── Phase 3: 关系构建（中成本）
│   3a: 符号规则引擎（新增，零成本）
│       └── 高置信度候选直接入库，低置信度标记待验证
│   3b: L2 因果链语义验证（LLM 验证）
│       └── 验证 Phase 3a 的待验证候选 + Layer 1-3 的 LLM 路径
```

符号规则引擎在 Phase 3a 中执行，因为它是纯 SQL 操作，成本几乎为零，且不依赖任何 LLM 调用。它发现的因果候选一部分直接入库（高置信度），一部分标记为待验证，留给 3b 的 LLM 处理。

### L3：抽象层（管道）

L3 本身是处理管道（process），不负责存储。它的输入来自 L1 事件池，产出物（行为模式、静态知识）持久化在 L1 对应的池中，并带有完整的生命周期管理（如行为模式的 status 状态机）。

管道式处理，连接 L1→L2→L4→L5：

| 管道 | 输入 | 输出 | 触发 |
|------|------|------|------|
| **模式发现** | 事件池事实 | 行为模式池 / 情感模式 | 定时 + 情绪转折检测 |
| **知识归纳** | 多个事件事实 | 静态知识池（含 abstracts_from 映射） | 定时 |

**抽象管道触发机制：双轨触发**

| 触发方式 | 适用场景 | 时机 | 产出 |
|---------|---------|------|------|
| **情绪转折检测** | 情感层面抽象 | 实时，检测到情绪突变时 | 情感洞察 + 映射 |
| **定时抽象** | 知识层面抽象 | 每 N 条新事实 / 每 M 小时 | 模式归纳 + 映射 |

**情绪转折检测（双通道）：**

```
通道 A：VAD 位移检测（主，确定性）
  ┌─────────────────────────────────────────────┐
  │  从 emotion_events 取最近 N 条 VAD 序列      │
  │                                              │
  │  计算相邻事件间的 VAD 位移：                   │
  │    Δvalence = |v₂ - v₁|                      │
  │    Δarousal  = |a₂ - a₁|                     │
  │    Δdominance = |d₂ - d₁|                    │
  │                                              │
  │  触发条件（任一满足）：                        │
  │    Δvalence > 0.5  → 情感极性翻转             │
  │    Δarousal > 0.4   → 唤醒度骤变              │
  │    Δdominance > 0.4 → 掌控感突变              │
  │    ||ΔVAD|| > 0.6   → 综合大位移             │
  │                                              │
  │  → 确定性触发，零 LLM 成本                    │
  └─────────────────────────────────────────────┘

通道 B：LLM 语义检测（辅，兜底）
  ┌─────────────────────────────────────────────┐
  │  在 LLM 多维度提取时同步输出：                 │
  │    "is_emotional_turning_point": true/false   │
  │    "turning_point_reason": "..."              │
  │                                              │
  │  适用场景：                                    │
  │    - VAD 位移小但语义重要（如平静地说"我辞职了"）│
  │    - 长时间沉默后的首次发言                     │
  │    - 自我披露、重要事件分享                     │
  │                                              │
  │  → 补充 VAD 通道的盲区                        │
  └─────────────────────────────────────────────┘

触发逻辑：
  if 通道 A 触发 or 通道 B 触发:
      回顾近期情节 → LLM 分析情绪模式 → 产出情感抽象事实
      写入静态知识池 + 通过 abstracts_from 映射回源情节
```

**为什么双通道：**

| 维度 | VAD 位移（通道 A） | LLM 语义（通道 B） |
|------|-------------------|-------------------|
| 成本 | 零（纯计算） | 高（每次对话都要判断） |
| 确定性 | ✅ 固定阈值，可复现 | ❌ 模型间/调用间不一致 |
| 能检测 | 情感强度的剧烈变化 | 语义上的"重要时刻" |
| 不能检测 | 平静但重要的事件 | 需要统一标准 |

**定时抽象：**
- 扫描未处理的情节事实
- 按实体/主题聚类 → LLM 分析模式 → 产出知识层面抽象事实
- 写入静态知识池/行为模式池 + 映射

#### 抽象管道的循环依赖问题（2026-06-13 讨论）

**问题：** 抽象管道存在三个循环依赖：
1. 抽象产物被写入 L1 后，可能再次被 L3 当作原材料抽象（无意义循环）
2. L3 需要 L2 的因果链，但因果链需要 L3 的语义理解（鸡生蛋蛋生鸡）
3. 新抽象事实 → 新关系 → 触发新抽象 → 无限循环

**核心洞察：** 抽象可以跨多级继续（类似 LLM 的 autoregressive 生成），关键不是"能不能继续"，而是"什么时候该停"。

##### 循环 ①：抽象产物再被抽象 — 允许，自然收敛

类比 LLM 生成：前面的输出作为后续输入，直到没什么可说的为止。

**终止条件（六重保障）：**

| 终止条件 | 机制 | 说明 |
|---------|------|------|
| **信息增益衰减** | 新产出 < 输入 × 0.3 | 越往上越少，自然收敛 |
| **新颖性检查** | 产出与已有同层事实语义相似度 < 0.85 | 防止"积极参与"→"非常积极参与"废话循环 |
| **跨层语义冗余检查** | 新产出与所有历史产出（跨层）最大余弦相似度 > 0.9 → 强制终止 | 防止跨层重复，不依赖 LLM 判断 |
| **置信度门槛递增** | L0→L1: ≥0.6, L1→L2: ≥0.7, L2→L3: ≥0.8 | 越抽象需要越强证据 |
| **LLM 自检** | "原始事件中是否还有未被覆盖的重要模式？" | 模型自己判断 EOS |
| **硬性上限（兜底）** | 最大 3-4 轮，最大 Level 3-4 | 防止极端情况 |

```
执行流程：
  Round 1: 300条事件 → 50条抽象 (level=1) 压缩比6:1 ✅
  Round 2: 50条抽象 → 8条信念 (level=2) 压缩比6:1 ✅
  Round 3: 8条信念 → 1条特质 (level=3) 置信度0.82≥0.8 ✅
  Round 4: 1条特质 → 0条产出 → 跨层冗余检查通过 → LLM自检"无新东西" → 🛑 终止
```

##### 跨层语义冗余检查的设计

**定位：** precision 闸门，优先级高于 LLM 自检。

| 维度 | LLM 自检 | 跨层语义冗余检查 |
|------|---------|----------------|
| 问题 | "原始事件里还有没覆盖的模式吗？" | "本轮产出和已有产出（跨层）重复吗？" |
| 方向 | **recall**（有没有遗漏） | **precision**（有没有冗余） |
| 能检测 | 遗漏的模式、新角度 | 同义废话、原地打转、跨层重复 |
| 不能检测 | 产出是否真的是废话 | 是否遗漏了重要模式 |

**决策逻辑：**

| LLM 自检 | 跨层冗余检查 | 结果 |
|----------|-------------|------|
| 还有 | ≤0.9（有新东西） | ✅ 继续 |
| 还有 | >0.9（废话） | 🛑 终止（相似度优先） |
| 没了 | ≤0.9 | 🛑 终止 |
| 没了 | >0.9（矛盾） | 🛑 终止（保守策略，宁可少抽不可循环） |

**与条件②（新颖性检查）的关系：**

两者可合并为统一语义冗余检查：

```
统一语义冗余检查：
  new_embed = embed(new_output)
  for each existing_fact in ALL_LEVELS:
      sim = cosine(new_embed, existing_fact.embedding)
      if sim > threshold:
          if existing_fact.level == current_level:
              threshold = 0.85  # 同层更严格
          else:
              threshold = 0.90  # 跨层稍宽松
          → 丢弃该产出 / 强制终止
```

**关键设计决策：** 跨层冗余检查不替代 LLM 自检，而是互补。LLM 自检负责 recall（是否遗漏模式），跨层冗余检查负责 precision（产出是否真有新信息）。两者结合形成完整的终止判断。LLM 自检的 false positive（说"还有"但产出废话）由跨层冗余检查兜底；LLM 自检的 false negative（说"没了"但实际有遗漏）暂时没有自动兜底，但保守策略（宁可少抽不可循环）是合理的工程取舍。

##### 循环 ②：L3 需要 L2，L2 需要 L3 — 分两阶段

```
阶段 1（L3 之前）：统计层面 — 不需要语义理解
  时间纠缠：纯时间邻近度，零成本全覆盖
  实体图：co_occur 统计
  时间链：LLM 提取时标注（不依赖 L3）

阶段 2（L3 之后）：语义层面 — 用 L3 的抽象知识精炼
  因果链：时间纠缠候选对 + L3 抽象知识 → LLM 验证
  情感轨迹：L3 情感模式 + 时间链 → 构建
```

**L3 跑之前，L2 已有基础关系可用（时间纠缠 + 时间链），L3 不需要等因果链。**

##### 循环 ③：新事实触发无限循环 — 冷却 + 阈值

```
触发条件（同时满足）：
  1. 距上次抽象 ≥ N 小时（冷却期）
  2. 新增原始事件 ≥ M 条（足够新材料）
  3. 当前处于睡眠周期（不打扰在线服务）

终止条件：
  - 本轮无新产出（信息增益不足）
  - 或 LLM 自检返回"无新东西"
  - 或达到最大迭代轮次
```

**核心原则：L2 的统计层（时间纠缠）是 L3 的前提，L3 的产出是 L2 语义层（因果链）的输入，两者交替迭代而非循环依赖。**

### L4：叙事层（故事线 — 人生主干）

**双层叙事：持久化人生主线 + 按需动态细节。**

L4 不是"非静态存储"的临时视图，而是**持久化的人生主干**——一个人的生命叙事有稳定的主干脉络，在此基础上可以按需构建不同角度的细节叙事。

```
┌─────────────────────────────────────────┐
│  动态细节（按需构建）                     │
│  ┌─────────────────────────────────────┐│
│  │ "Caroline 和 Melanie 的友谊故事"    ││
│  │ "Caroline 的领养申请心路历程"       ││
│  │ "Caroline 2023年夏天的转折"        ││
│  └─────────────────────────────────────┘│
│                    ↑ 基于主干+具体query   │
│  ┌─────────────────────────────────────┐│
│  │  持久化主干（定时构建+缓存）          ││
│  │  "Caroline 的人生主线：              ││
│  │   寻找自我→融入社群→遭遇挫折→       ││
│  │   新的方向→从被帮助到帮助他人"       ││
│  └─────────────────────────────────────┘│
│                    ↑ 从 L2+L3 定时提炼    │
└─────────────────────────────────────────┘
```

**持久化主干：**
- 定时构建（睡眠周期），缓存到下次更新
- 覆盖整个人生的主线叙事，有版本号
- 从 L2 的时间链+因果链+情感轨迹 + L3 的行为模式提炼
- 作为 L5 的输入之一

**动态细节：**
- 按需构建，基于持久化主干 + 具体 query 角度
- 回答"Caroline 和 Melanie 的关系是怎么发展的"这类问题
- 不持久化，用完即弃

例子：
```
持久化主干：
"Caroline 2023年的成长故事：
  第一章：寻找自我（5月）→ 参加支持小组，公开演讲
  第二章：融入社群（6-7月）→ 骄傲游行，归属感上升
  第三章：遭遇挫折（7月）→ 徒步冲突，但韧性恢复
  第四章：新的方向（8-10月）→ 从被接纳到给予支持，领养申请"

动态细节（基于主干+query）：
  Q: "Caroline 和 Melanie 的关系"
  → "从支持小组相识 → 一起参加骄傲游行 → 徒步冲突后互相支持 → 友谊深化"
```

#### L4 与 L5 的关系：内在一外在

L4 和 L5 是硬币的两面——L5 是内在人格模型，L4 是外在人生故事。

```
L5（内在 — 人格）                L4（外在 — 故事）
─────────────────                ─────────────────
核心价值观                      人生选择（反映价值观）
情绪调节模式                    情感转折（反映情绪模式）
决策倾向                        关键决策（反映决策倾向）
关系模式                        重要关系（反映关系模式）
当前人生阶段                    当前故事章节

L5 解释"为什么"                  L4 讲述"发生了什么"
L5 是原因                        L4 是结果
L5 是内在模型                    L4 是外在表现
```

**双向验证：**

```
L1-L3 事实+模式
    ↓
L5 构建人格模型："Caroline 坚韧、社群导向"
    ↓ 提炼为叙事
L4 人生主线（外在表现）：
  "因为社群导向，她加入支持小组、参加骄傲游行..."
    ↓ 反馈验证
L4 故事中的行为是否与 L5 人格模型一致？
  ✅ 一致 → 强化人格模型
  ❌ 不一致 → 触发矛盾检测 → 更新人格模型
```

**L5 的输入包含 L4：**
- L0 原始对话 + L1 三池事实 + L2 关系 + L3 行为模式/情感模式 + **L4 人生主干**
- L4 人生主干提供了人格模型的"外在表现"参照，帮助 L5 验证和精炼人格模型

---

### L5：灵魂层（人格建模 + 行为预测）

**核心价值：** 不只是理解一个人的过去，而是**预测他的未来**。

```
L5 灵魂层 = 人格模型（用于预测）

┌─────────────────────────────────────────────┐
│              人格模型结构                      │
│                                              │
│  核心价值观: 什么对他最重要，优先级如何排列      │
│  情绪调节模式: 压力/挫折/快乐时的行为倾向        │
│  决策倾向: 面对冲突/选择/挫折时的典型反应        │
│  关系模式: 社交倾向、依赖模式、信任边界          │
│  当前人生阶段: 处于什么阶段，正在经历什么转变     │
└─────────────────────────────────────────────┘
```

**灵魂层的价值对比：**

| | 检索式回答（PersonaMem） | 灵魂层回答 |
|--|----------------------|----------|
| Q: "Caroline 是什么样的人" | 从 top-N 事实拼凑画像 | 结构化人格模型 |
| Q: "Caroline 遇到压力会怎样" | "上次她去画了画"（过去） | "她会先创作释放，再找朋友倾诉"（预测） |
| Q: "该不该告诉 Caroline 坏消息" | 无法判断 | "她有韧性恢复力，但需要时间缓冲，建议温柔方式" |

**构建方式：从 L0-L4 记忆中涌现，而非手动标注。**
- 输入：L0 原始对话 + L1 三池事实 + L2 关系（时间链/因果链/实体图/情感轨迹）+ L3 行为模式/情感模式 + L4 人生主干
- 即 L0-L4 的所有产出都是灵魂层素材，L5 综合所有下层信息构建人格模型。其中 L4 人生主干提供了人格模型的"外在表现"参照，帮助 L5 验证和精炼
- 输出：结构化人格模型
- 高质量检索是 L5 的原材料（PersonaMem 的洞察），L5 是深加工

**分阶段交付：**

| Phase | 内容 | 依赖 |
|-------|------|------|
| **Phase 1** | L5 作为人格模型构建者 — 从 L1-L3 事实/模式 + L4 人生主干中提炼人物核心特质 | L1 + L2 + L3 + L4 主干 |
| **Phase 2** | L5 作为预测引擎 — 人格模型 + 当前上下文 → 预测行为 | Phase 1 + 检索增强 |

> Phase 1 → Phase 2 的过渡条件：当 Phase 1 积累的叙事数据足以支撑稳定的人格模型时（如覆盖多个时间跨度的叙事 ≥ N 条），自动进入 Phase 2。具体阈值实现时确定。

```
Phase 1 例子：
  多个叙事 → 提炼 → "Caroline 的核心：坚韧、社群导向、有同理心"

Phase 2 例子：
  人格模型 + "Caroline 今天工作好累"
  → 预测分布:
      画画释放情绪       ████████████████ 60%
      找 Melanie 聊天    ██████          25%
      一个人待着         ██              10%
      暴饮暴食           ▏                5%
  → Agent 主动: "要不要画画放松一下？我记得你每次压力大时创作都能让你平静"
  → 如果 Caroline 实际去找 Melanie 聊天了 → 落在 p=25% 的预测内，正常行为
```

**L5 灵魂层与矛盾检测的关系：**

L5 的预测能力是矛盾检测的**核心基准线**——只有知道一个人"接下来想做什么"，才能判断实际发生的事情是否矛盾。

#### 预测是概率分布，而非单点

人格模型的预测不是一条确定的事实，而是**多条事实带概率的分布**——就像人类的决策一样，没发生的事情永远存在概率，只是取概率最大的作为最可能的行为。

```
L5 预测分布示例（Caroline 压力大时）:
  画画释放情绪       ████████████████ 60%
  找朋友倾诉         ██████          25%
  一个人待着         ██              10%
  暴饮暴食           ▏                5%
```

**分布置信度**由分布的集中程度决定：
- 分布集中（如 80%/12%/5%/3%）→ 模型确定性强，置信度高
- 分布分散（如 25%/25%/25%/25%）→ 模型不确定，置信度低
- 量化方式：`分布置信度 = 1 - 分布的熵 / 最大熵`

#### 矛盾检测 = 惊讶度 × 置信度

```
惊讶度 = 1 - P(新事实)   — 新事实在预测分布中的概率越低越惊讶

矛盾信号强度 = L5 分布置信度 × 惊讶度
```

```
例子：
  预测分布: 画画 60% | 找朋友 25% | 独处 10% | 暴饮暴食 5%

  新事实 = 画画       → 惊讶度 0.4  → 低信号，强化模型
  新事实 = 找朋友     → 惊讶度 0.75 → 中等信号，微强化
  新事实 = 独处       → 惊讶度 0.9  → 较高信号，标记待观察
  新事实 = 暴饮暴食   → 惊讶度 0.95 → 高信号，触发检测
  新事实 = 完全意外行为 → 惊讶度 1.0 → 强信号 🔴
```

**反差检索（互补机制，Phase 2+）：** 矛盾检测输出"惊讶度分数"，反差检索输出"历史上预测失败的具体记忆"——两者互补。当矛盾信号强时，反差检索自动追溯历史上处于相似预测-实际偏差的记忆，为矛盾分析提供历史证据链。详见检索设计文档 §3.7。

#### 三层递进分析

```
新事实写入
    ↓
L5 人格模型生成预测分布
    ↓
计算惊讶度 × 置信度 → 矛盾信号强度
    ↓
┌──────────────┬──────────────┬──────────────┐
│ 强信号       │ 中等信号     │ 弱信号       │
│ (≥0.7)       │ (0.3~0.7)    │ (<0.3)       │
├──────────────┼──────────────┼──────────────┤
│ 直接触发     │ 标记待观察   │ 忽略         │
│ 三层递进分析 │ 积累N条再触发│ 仅更新分布   │
└──────────────┴──────────────┴──────────────┘
> 以上阈值为概念示例，实现时需根据实际数据调参。
    ↓
三层递进分析：
  第一层：时间裁决（简单情况）
    → 新事实时间更新 → 替代旧事实，更新人格模型
    → 不降置信度（人在变化是正常的）
  第二层：触发抽象管道（中等情况）
    → 矛盾本身就是模式信号
    → 抽象管道分析：真实改变还是前后不一致？
  第三层：叙事/灵魂层判断（深层情况）
    → 多个"待观察"积累 → 深层分析
    → 成长/变化？说谎？认知失调？
    ↓
更新预测分布（贝叶斯更新）
    ↓
更准的 L5 → 更精准的分布 → 更好的矛盾检测
```

#### 预测分布的更新

```
新事实发生后：
  事实在分布内 → 对应概率微调 ↑，其他微调 ↓（归一化）
  事实不在分布内 → 新增一条概率，整体归一化
```

```
例子：
  当前分布: 画画 60% | 找朋友 25% | 独处 10% | 其他 5%

  她画画了 → 更新:
    画画 63% ↑ | 找朋友 23% ↓ | 独处 9% ↓ | 其他 5% →

  她暴饮暴食了（不在分布内）→ 更新:
    画画 50% ↓ | 找朋友 20% ↓ | 独处 8% ↓ | 其他 4% ↓
    暴饮暴食 18% 🆕
```

#### 自我实现预言隔离（干预-因果隔离）

L5 的预测不只是内部模型，Agent 可能会将预测表达给用户（如"你是不是想吃东西了？"），这种表达本身可能**诱导用户行为**，造成虚假的预测验证。

**核心问题：** 系统需要区分"用户自然流露的行为"和"被 Agent 表达过的预测所诱导的行为"，否则 L5 会陷入自我实现的反馈循环。

**隔离机制：**

| 机制 | 说明 | 实现方式 |
|:----|:----|:--------|
| **干预标记** | Agent 向用户表达某个预测时，标记该预测为 `intervened` | 在预测分布中增加 `intervened_probs` 字段 |
| **置信度惩罚** | 被干预过的预测如果被后续行为匹配，置信度更新幅度减半 | `Δp = 0.5 × Δp_normal` |
| **因果隔离** | L5 训练时区分"自然行为"和"可能被诱导的行为" | 被干预预测匹配的行为标记为 `source=agent_intervention`，不参与人格模型更新 |
| **反事实基线** | 记录干预前的预测分布作为基线，用于对比分析 | 干预前快照存到 `prediction_snapshots` |

```
Agent 表达预测 → 标记 intervened
    ↓
用户后续行为匹配了该预测
    ↓
┌─────────────────────────────────────────────┐
│  判断：是自然行为还是被诱导行为？             │
│                                              │
│  无法确定 → 保守处理：                       │
│    - 更新预测分布时 Δp 减半                  │
│    - 不更新 L5 人格模型（避免强化循环）       │
│    - 标记为 source=agent_intervention        │
│                                              │
│  可确定（如用户明确说"我才不是因为你说的"）   │
│    → 不更新预测分布                          │
│    → 降低 Agent 对该预测的表达优先级          │
└─────────────────────────────────────────────┘
```

**与矛盾检测的关系：** 被干预标记的行为即使匹配了预测，也不降低惊讶度——系统仍然认为"用户可能只是被诱导了，不是真实行为模式"。

#### 五类矛盾形态在 L5 框架下的统一检测

| 形态 | 检测方式 | 解决层 | 说明 |
|------|---------|-------|------|
| **直接否定** | 惊讶度高 | Layer 1 时间裁决 | 正常人生变化，更新模型 |
| **状态更新** | 惊讶度高 | Layer 1 时间裁决 | 同上 |
| **隐含矛盾** 🔥 | 惊讶度高 | Layer 2→3 抽象/叙事 | L5 让不可检测变可检测 |
| **跨维度矛盾** | 多信号惊讶度不一致 | Layer 2→3 | L5 天然整合多维度 |
| **言行矛盾** 🔥 | 声明vs行为惊讶度差异 | Layer 3 叙事/灵魂层 | 需要 L5 人格模型作为基准线 |

#### 自我完善的闭环

```
L0-L4 记忆积累 → L5 人格建模 → L5 生成预测分布
    ↓                                          ↓
新事实 vs 预测分布 → 惊讶度 × 置信度 → 矛盾检测
    ↓
更新人格模型/更新分布/深层分析
    ↓
更准确的 L5 → 更精准的分布 → 更精准的矛盾检测
```

L5 灵魂层因此从"高级特性"升级为**矛盾检测的核心基础设施**。

#### 远期展望：从个体人格到社会模拟

当多个个体的 L5 灵魂层都足够完善时，将他们放在一起交互，就可以自然涌现出社会模拟——构建一个接近真实的虚拟世界。

每个个体拥有自己独立的 L0-L5 记忆系统，带着从真实对话中涌现的人格模型进入交互。当个体 A 对个体 B 说话时，B 的 L5 会预测"A 说这话是什么意思"，基于预测做出回应；A 再基于 B 的回应更新对 B 的人格模型。如此循环，社会关系自然涌现。

这与斯坦福小镇（Generative Agents）的核心区别：

| 维度 | 斯坦福小镇 | 本架构的潜力 |
|------|:---------:|:-----------:|
| 人设来源 | 手动编写 | 从真实对话涌现 |
| 记忆深度 | 扁平记忆流 | L0-L5 分层 |
| 行为预测 | 无 | L5 概率分布预测 |
| 因果理解 | 无 | 四层因果推理 |
| 矛盾检测 | 无 | 惊讶度×置信度 |
| 人格演化 | 静态 | 贝叶斯更新，持续演化 |

微观层面，个体间的每一次交互都会更新彼此的人格模型；宏观层面，多次交互后群体中会自然涌现出朋友关系、影响力层级、群体共识、社会规范等社会现象。

**这不是额外功能，而是架构设计本身就隐含的可能性。** 一旦每个个体的 L5 足够完善，社会模拟就是自然涌现的结果，不需要额外的"社会模拟模块"。

### 遗忘机制（贯穿层）

**核心理念：永远保留，只是检索成本不同。** 类比人脑——不是忘了，是检索成本变高了。

遗忘不是删除，而是**冷热分级 + 检索策略分级**的组合：

```
冷热分级决定检索优先级：
  🔥 热 → 🌤️ 温 → ❄️ 冷 → 🧊 冰

检索策略分级决定检索方式：
  🔥 原始事实全量 embedding (float32)
  🌤️ 原始事实全量 embedding (float32)
  ❄️ L3 摘要事实 embedding (float16 量化) + 时间范围过滤
  🧊 仅关键词索引 (FTS5)
```

> ❄️ 阶段使用 L3 抽象层生成的摘要事实的 embedding（float16 量化），而非原始事实。1 个摘要向量可代表约 10 条原始对话，在保留语义检索能力的同时大幅降低存储成本。🧊 阶段保持 FTS5 关键词检索，确保极端冷数据仍有最低限度的可发现性。

#### 热度模型

```
热度 = f(recency, access_frequency, importance, 是否被替代)

🔥 热 → 🌤️ 温 → ❄️ 冷 → 🧊 冰
```

| 级别 | 触发条件 | 检索行为 | 权重 | 检索策略 | 类比 |
|------|---------|---------|------|---------|------|
| 🔥 **热** | 最近 N 天提取 / 高频访问 | 默认参与检索 | × 1.0 | 全量 embedding 检索 (float32) | "脱口而出" |
| 🌤️ **温** | 超过 N 天未访问 / 中频 | 默认参与检索 | × 0.7 | 全量 embedding 检索 (float32) | "想一下能想起来" |
| ❄️ **冷** | 被抽象替代 / 长期未访问 | 需 `memory="deep"` | × 0.4 | L3 摘要事实 embedding (float16 量化) + 时间范围过滤 | "努力回忆" |
| 🧊 **冰** | 深度归档 / 仅历史价值 | 需 `memory="all"` | × 0.2 | 仅关键词索引 (FTS5) | "需要线索才能想起" |

#### 冷却与加热

```
冷却规则：
  新事实 → 🔥 热
      ↓ 超过 7 天未访问
  🌤️ 温
      ↓ 超过 30 天未访问 或 被 L3 抽象替代
  ❄️ 冷
      ↓ 超过 90 天 且 无叙事关键标记
  🧊 冰（但永远不删）

加热规则：
  被检索命中 → 热度 +1 级
  被 L4 标记为叙事关键节点 → 永久保持温以上
  被 L5 标记为核心特质相关 → 永久保持温以上
```

#### 各层不再打架，而是叠加影响冷却速度

```
L1 池：低 importance → 冷却加速 × 1.5（importance 标度 0.0~1.0）
L2 关系层：高关系密度 → 冷却减速 × 0.5
L3 抽象层：已被抽象替代 → 冷却加速 × 2.0
L4 叙事层：叙事关键节点 → 冷却减速 × 0.3
L5 灵魂层：核心特质相关 → 冷却减速 × 0.3

聚合方式：几何平均（仅活跃层）
  active_factors = [f for f in [L1,L2,L3,L4,L5] if f != 1.0]
  综合冷却系数 = (∏ active_factors) ^ (1 / len(active_factors))
```

**为什么不用乘法：** 乘法随层数增加结果越来越极端。全部减速时 0.5×0.3×0.3=0.045（慢 22 倍），几何平均 = 0.356（慢 2.8 倍）。加速和减速自然抵消，无需魔法 clamp 阈值。

**例子：**
```
事实: "Caroline 2023-05-08 参加了支持小组"
  L1: importance=0.6 → 加速 × 1.5
  L2: 12条关系链 → 减速 × 0.5
  L3: 已抽象替代 → 加速 × 2.0
  L4: 叙事关键节点 → 减速 × 0.3
  ────────────────────────────
  active_factors = [1.5, 0.5, 2.0, 0.3]
  综合: (1.5 × 0.5 × 2.0 × 0.3) ^ (1/4) = 0.45 ^ 0.25 = 0.82
  → 冷却稍慢，长期保持温/热 ✅
```

#### 检索深度路由

热度路由由 FusionEngine 的 `HEAT_STRATEGY` 控制，通过 `priority` 字段决定各热度级别的检索优先级（详见检索设计文档 §5.3）：

| 热度 | priority | 检索策略 |
|:---:|:--------:|:--------|
| 🔥 热 | 1.0 | float32 embedding + 完整 PPR |
| 🌤️ 温 | 0.8 | float32 embedding + 剪枝 PPR |
| ❄️ 冷 | 0.4 | fp16 量化 embedding + 无图检索 |
| 🧊 冰 | 0.1 | 仅 FTS5 关键词 |

默认检索覆盖 🔥+🌤️。`memory="deep"` 增加 ❄️，`memory="all"` 包括 🧊。`memory` 参数保留为**用户显式覆盖接口**——当用户要求"搜得更深"时，Agent 可主动调用扩展热度范围。默认路由由 QueryClassifier 自动完成，`memory` 参数仅用于显式覆盖，两者不冲突。

**对比传统遗忘仲裁：**

| | 遗忘仲裁 | 冷热分级 |
|--|---------|---------|
| 核心理念 | 删不删 | 好不好查 |
| 各层关系 | 冲突 → 仲裁 | 叠加 → 冷却系数 |
| 出错风险 | 高（误删不可逆） | 低（只是难查，还在） |
| 实现复杂度 | 高（仲裁逻辑） | 低（冷却公式） |
| 存储 | 需要清理 | 永远保留 |
| 类比 | 文件系统 | 人脑记忆 |

#### 隐私擦除层（用户删除权）

**核心理念：** "永远保留"是系统默认行为，但用户有权利真正删除自己的数据。删除不只是"检索不到"，而是从所有层中彻底移除。

**删除需二次确认：** 用户请求真实删除时，系统必须二次确认（"确定要永久删除这条记录吗？此操作不可撤销"），确认完成后立即执行。

| 删除级别 | 影响范围 | 操作 | 代价 |
|:--------|:--------|:----|:----|
| **L1 级删除** | 删除单条事实 | 从 L1 事实表删除，L0 微事实标记为 `deleted` | 低（单条 SQL） |
| **L3 级删除** | 删除事实及其衍生的抽象 | 删除事实 + 重新计算受影响的 L3 抽象事实 | 中（需触发部分睡眠周期） |
| **L5 级删除** | 删除事实及其对人格模型的影响 | 删除事实 + 标记 L5 中受影响的向量维度 + 睡眠周期重新计算 L5 | 高（需完整睡眠周期） |
| **全量擦除** | 删除某个人的所有数据 | 清空该 person 在所有层的全部数据 | 最高（但最彻底） |

**L5 级删除的实现方式：**

```
用户请求删除事实 F
    ↓
从 L1 删除 F，从 L0 标记 deleted
    ↓
┌─────────────────────────────────────────────┐
│  L5 受影响范围计算                           │
│                                              │
│  1. 找到 F 参与过的所有 L3 抽象事实           │
│  2. 找到这些抽象事实贡献过的 L5 人格维度       │
│  3. 标记这些维度为 "pending_recompute"        │
│  4. 睡眠周期中重新计算受影响的 L5 部分         │
│     （不重建整个 L5，只重新计算受影响维度）     │
└─────────────────────────────────────────────┘
    ↓
睡眠周期中：
  受影响的 L5 维度 ← 基于剩余事实重新计算
  其他维度不变
```

#### 用户屏蔽层（不提，不删）

**核心理念：** 大多数情况下用户不是想删数据，而是不想让系统提某些事。用 `user_blocks` 表记录"不提"，数据本身永远保留，检索时跳过。

```sql
-- 用户屏蔽记录（统一处理所有类型的屏蔽）
user_blocks:
  block_id, person,
  block_type TEXT,          -- 屏蔽类型
    -- 'trigger_topic'    = 屏蔽某个情感触发话题
    -- 'trigger_entity'   = 屏蔽某个实体触发关联
    -- 'fact'             = 屏蔽某条事实（不输出）
    -- 'emotion_event'    = 屏蔽某条情感事件
    -- 'behavior_pattern' = 屏蔽某个行为模式
    -- 'emotion_pattern'  = 屏蔽某个情感模式
    -- 'topic'            = 屏蔽某个话题（所有相关数据）
  block_value TEXT,         -- 屏蔽的值
    -- '身高' / '前任' / fact_id=1001 / event_id=50 / ...
  blocked_at,
  reason TEXT,              -- 用户提供的原因（可选）

  UNIQUE(person, block_type, block_value)
```

**检索时过滤：** 所有检索管道统一在 FusionEngine 中过滤被屏蔽的内容：

```python
def _apply_blocks(results, blocks):
    if not blocks:
        return results
    
    blocked_facts = {b.block_value for b in blocks if b.block_type == 'fact'}
    blocked_events = {b.block_value for b in blocks if b.block_type == 'emotion_event'}
    blocked_topics = {b.block_value for b in blocks if b.block_type == 'topic'}
    
    return [
        r for r in results
        if r.fact_id not in blocked_facts
        and getattr(r, 'event_id', None) not in blocked_events
        and not any(t in str(r.content) for t in blocked_topics)
    ]
```

**情感回避中的使用：**

```python
def get_emotion_triggers(person, topic):
    return db.query("""
        SELECT * FROM emotion_triggers
        WHERE person = ?
        AND (trigger_type, trigger_value) NOT IN (
            SELECT block_type, block_value FROM user_blocks
            WHERE person = ? AND block_type IN ('trigger_topic', 'trigger_entity')
        )
    """, person, person)
```

**与"永远保留"的关系：**

```
用户请求屏蔽 → 不是删除，只是记录"不提"
    ↓
数据：全部保留 ✅
检索：跳过被屏蔽的内容 ✅
可逆：取消屏蔽后数据立即可用 ✅
派生：睡眠周期正常聚合，输出时过滤 ✅
```

**用户屏蔽 vs 真实删除：**

```
用户："别提身高这个话题" → user_blocks（不提，可逆）
用户："把那条记录删了"   → 隐私擦除层（真删，需二次确认，不可逆）
```

**与"永远保留"原则的关系：**

```
默认行为：系统永远保留所有数据
用户请求删除 → 系统执行删除（尊重用户权利）
```

两者不矛盾——"永远保留"是系统层面的默认策略，用户删除权是用户层面的控制能力。系统不主动删，但用户要求删时能删干净。

**安全考虑：**
- 删除操作记录到审计日志（谁、什么时候、删了什么）
- 支持软删除（先标记 `deleted_at`，N 天后硬删除）
- L5 重新计算期间，旧人格模型继续服务（不影响在线体验）

## 六、检索路由设计

> 讨论日期：2026-06-15 → 2026-06-16（重构）
> 决策：四阶段检索管道 — QueryClassifier → LayerRouter → ParallelRetrieval → FusionEngine
> 完整内容已移入独立文档：[`v2-retrieval-design.md`](v2-retrieval-design.md)

### 6.1 核心思路（摘要）

放弃简单的"L0+L1 线性加权 + L2-L5 附加上下文"方案，改为**四阶段检索管道**：

```
Query → QueryClassifier → LayerRouter → ParallelRetrieval → FusionEngine → Output
```

**QueryClassifier**：将 query 分为 9 种类型（fact/causal/prediction/contradiction/relation/emotion/narrative/persona/general），每种类型对应不同的目标层和路由策略。两阶段分类：关键词规则（快速路径）+ LLM 兜底（低置信度时）。

**LayerRouter**：根据 query 类型决定查哪些层，结合渐进激活检查（未激活层优雅降级）。

**ParallelRetrieval**：各层并行检索，每层实现统一 `RetrievalSource` 接口。各层检索策略：

| 层 | 检索策略 | 排序信号 |
|:--|:--------|:--------|
| L0 | FTS5 + 可选 embedding | BM25 + 时间衰减 + 语义 |
| L1 | 增强三维评分 + 池间路由 | 三维评分 × trust × heat_zone_weight |
| L2 | PPR + 四层递进因果链 + 时间链 + 因果子图游走（Phase 2+） | PPR分数 / 因果强度 / 时间接近度 / 因果深度 |
| L3 | 聚类匹配（马氏距离）+ Parent-Child 源事实回溯 | 聚类相干性 × 语义相似度 × 源事实增益 |
| L4 | 版本化叙事主干 + 按需动态细节 + 时间折叠（Phase 2+） | 叙事相关性 / 时间窗过滤 |
| L5 | 人格维度匹配 + 行为概率检索 + 心理探针检索（Phase 2+，零 LLM 调用） + 反差检索（Phase 2+） | 维度匹配度 × 置信度 / 心理状态相似度 / 反差分数 |

**FusionEngine**：异构结果归一化 → 跨层加权 → 去重 → MMR 重排序 → 结构化上下文包输出。

### 6.2 与热度检索路由的关系

| 路由维度 | 作用 | 说明 |
|:--------|:----|:-----|
| **跨层路由**（本条） | 查哪些层 | QueryClassifier 决定目标层 |
| **层内热度路由**（上文遗忘机制） | 查多热的记录 | 🔥+🌤️ 默认，❄️ 需 deep，🧊 需 all |

两者正交：先决定查哪些层，再决定查多热的记录。

> 详见 [`docs/v2-retrieval-design.md`](v2-retrieval-design.md) — 包含完整四阶段管道设计、各层检索算法、FusionEngine、MMR 重排序、热度交互、分阶段实现路径等。

## 七、睡眠周期调度器

> 讨论日期：2026-06-15
> 决策：混合策略 — 空闲检测为主 + 兜底定时强制触发

### 7.1 要调度的批量操作

| # | 操作 | 依赖 | 预估成本 | 所属阶段 |
|:-:|:----|:----|:--------|:--------|
| ① | L0→L1 冷晋升 | 无 | 中（LLM 批量提取） | Phase 2 |
| ② | 热度衰减计算 | 无 | 低（纯计算） | Phase 1 |
| ③ | L2 统计层（时间纠缠） | ① 完成后 | 低（纯计算） | Phase 1 |
| ④ | L3 抽象管道 | ①+③ 完成后 | 高（LLM 模式发现） | Phase 2 |
| ⑤ | L2 语义层（因果链） | ④ + 3a 完成后 | 中（LLM 验证 + 符号规则） | Phase 3 |
| ⑥ | L4 叙事主干更新 | ④+⑤ 完成后 | 中（LLM 叙事生成） | Phase 3 |
| ⑦ | L5 人格模型更新 | ⑥ 完成后 | 中（LLM 人格建模） | Phase 4 |
| ⑧ | 检索策略降级 | ② 完成后 | 低（纯计算） | Phase 4 |

**依赖链：**

```
① L0→L1 冷晋升
    ↓
② 热度衰减 + ③ L2 统计层（可并行）
    ↓
④ L3 抽象管道
    ↓
3a 符号规则引擎（纯 SQL，零成本）
    ↓
⑤ L2 语义层（因果链 LLM 验证）
    ↓
⑥ L4 叙事构建
    ↓
⑦ L5 人格模型更新
    ↓
⑧ 检索策略降级
```

### 7.2 触发条件

```
同时满足以下条件时触发睡眠周期：

1. 距上次睡眠周期 ≥ N 小时（默认 6h，防止过于频繁）
2. 新增原始事件 ≥ M 条（默认 20 条，有活干才跑）
3. 当前无活跃对话（用户超过 5 分钟没发消息）
4. 兜底定时：最长 24h 强制触发一次（即使一直有人聊天）
```

### 7.3 分阶段执行

```
┌─────────────────────────────────────────────────┐
│              睡眠周期执行流程                      │
├─────────────────────────────────────────────────┤
│                                                  │
│  Phase 0: 预热（~1s）                            │
│    检查触发条件，计算本次需要处理的数据量           │
│    估算总耗时，决定是否跳过某些阶段                │
│                                                  │
|  Phase 1: 数据准备（纯计算，~100ms）              │
│    ① 热度衰减计算                                │
│    ② L2 时间纠缠（统计层面）                      │
│    ③ 标记待晋升的 L0 微事实                       │
│                                                  │
│  Phase 2: LLM 批量（高成本，核心阶段）             │
│    ④ L0→L1 冷晋升（LLM 批量提取）                │
│    ⑤ L3 抽象管道（LLM 模式发现）                  │
│                                                  │
│  Phase 3: 关系构建（中成本）                      │
│    3a 符号规则引擎（纯 SQL，零成本）              │
│    ⑥ L2 因果链语义验证（LLM 验证）               │
│    ⑦ L4 叙事主干更新（LLM 叙事生成）              │
│                                                  │
│  Phase 4: 人格更新（中成本）                      │
│    ⑧ L5 人格模型增量更新（LLM）                  │
│    ⑨ 检索策略降级（纯计算）                       │
│                                                  │
│  Phase 5: 收尾（~10ms）                           │
│    记录本次执行统计（处理条数/耗时/LLM token）     │
│    更新 last_sleep_at 时间戳                      │
│                                                  │
└─────────────────────────────────────────────────┘
```

### 7.4 中断与恢复

```
关键原则：每个阶段都是幂等的，随时可以中断。

中断条件：
  - 用户发新消息 → 立即中断，保存 checkpoint
  - 达到最大执行时间（默认 30 分钟）→ 自然中断
  - LLM 调用失败 → 跳过当前阶段，下次重试

恢复机制：
  - 外层调度按阶段（Phase 1/2/3/4/5）检查 checkpoint，已完成的阶段跳过
  - 未完成的阶段从上一次中断点继续
  - Phase 2 内部按水位线恢复（每个 LLM 调用成功后写水位线）
```

**checkpoint 粒度：每个 LLM 调用成功后写水位线**

```
Phase 2: L0→L1 冷晋升
  checkpoint = {
      "phase": "phase2_cold_promotion",
      "last_processed_micro_fact_id": 370  ← 已成功晋升的微事实 ID
  }

  恢复时: SELECT * FROM micro_facts
          WHERE id > last_processed_micro_fact_id
          ORDER BY id LIMIT batch_size
```

**为什么不是阶段级或批级：**

| 粒度 | 问题 | 示例 |
|:----|:-----|:-----|
| **阶段级**（当前） | LLM 调用中途失败 → 已写入和未写入边界模糊 | 批 38 写到第 5 条时失败，恢复后从批 38 重试 → 前 5 条重复 |
| **批级** | 批内部分成功时无法精确恢复 | 同批 10 条中 7 条成功 3 条失败 → 重试整批浪费 |
| **水位线级** ✅ | 精确到单条微事实，零重复零遗漏 | 恢复时 `WHERE id > 370`，精确无歧义 |

**实现方式：** 每个 LLM 调用成功后，将本批最后一条微事实的 ID 写入 checkpoint。LLM 调用失败时不更新 checkpoint，下次重试同一批。checkpoint 表单行 UPDATE，成本可忽略。

### 7.5 增量原则

所有操作都是增量的，不重建：

| 操作 | 增量方式 |
|:----|:--------|
| L0→L1 冷晋升 | 只处理上次睡眠后新标记的微事实 |
| L3 抽象管道 | 只处理上次睡眠后新增的事实 |
| L4 叙事主干 | 增量追加，不重建整个叙事 |
| L5 人格模型 | 贝叶斯增量更新，不从头建模 |
| 热度衰减 | 每天统一计算一次衰减量 |
| Q 值评估 | 只处理上次睡眠后新被检索过的事实 |

### 7.6 执行策略变体

| 策略 | 适用场景 | 说明 |
|:----|:--------|:----|
| **完整周期** | 默认 | 所有阶段按序执行 |
| **快速周期** | 用户频繁使用 | 只跑 Phase 1+2（数据准备+冷晋升），跳过 L4+L5 |
| **强制周期** | 手动触发 | 忽略触发条件，立即执行全部阶段 |
| **维护周期** | 每周一次 | 额外执行完整性检查、数据一致性校验 |

## 八、L5 Phase 2 行为预测 — 向量空间方案

> 讨论日期：2026-06-15
> 决策：行为向量空间替代固定类别预测，采用"核心心理学维度 + GMM 行为模式维度"的混合架构
> 完整内容已移入独立文档：[`v2-behavior-prediction.md`](v2-behavior-prediction.md)

### 8.1 核心思路

```
不是"Caroline 压力大时会做什么（4 个选项）"
而是"Caroline 的行为向量空间"

每个人的 L5 人格模型定义 TA 专属的行为向量空间：
  - 空间维度 = 行为特征维度（心理学支撑 + 数据驱动补充）
  - 空间范围 = TA 历史上所有行为的向量分布
  - 空间密度 = 某些区域行为密集（高概率），某些区域稀疏（低概率）
```

### 8.2 维度结构

```
核心维度（12 维，心理学支撑）：
  大五人格映射    5 维  ← 与 L5 人格模型共享语义
  能量与动机      4 维  ← 行为驱动力
  VAD 情感        3 维  ← 与情感维度衔接（valence, arousal, dominance）

补充维度（3~5 维，数据驱动）：
  GMM 行为模式聚类  ← 覆盖长尾语义，每个模式可命名

总维度：15~17 维
```

### 8.3 整体实现路径

| Phase | 内容 | 数据要求 |
|:----|:----|:--------|
| **Phase 1（MVP）** | 固定 12 维核心维度（9 维映射 + 3 维 VAD 直接取）+ LLM Teacher 离线标注 + Student 多任务回归 + 条件高斯+三层递进上下文偏移 + Ledoit-Wolf 收缩 | ≥ 1 条（群体先验兜底） |
| **Phase 2（增强）** | GMM 行为模式维度 + embedding 映射模型训练 + GMM 多模式预测 + 群体先验 | ≥ 200 条 |
| **Phase 3（演进）** | 漂移检测 + 群体先验库 + 主动学习 + 校准 | ≥ 500 条 |
| **Phase 4（成熟）** | 人格模型版本管理 + 检索策略自动降级 | 依赖 L4 叙事稳定 |

> 详见 [`docs/v2-behavior-prediction.md`](v2-behavior-prediction.md) — 包含维度详解、向量映射方案、条件概率预测、空间成熟度、漂移检测、矛盾检测衔接等完整设计。

## 九、待完善环节（备忘）

> 以下环节经讨论确认为重要但非现阶段重点，记录备忘供后续阶段参考。

### 9.1 测试策略

| 维度 | 说明 |
|:----|:-----|
| 标注数据集 | 缺乏用于回归测试的标注数据集，无法量化检索质量变化 |
| 评估指标 | 需要定义召回率、精确率、MRR、NDCG 等指标 |
| 回归测试 | 每次检索算法变更后自动跑回归，防止退化 |
| 用户模拟 | 模拟多轮对话场景测试记忆提取和检索的端到端效果 |

### 9.2 并发控制

| 场景 | 风险 |
|:----|:-----|
| 睡眠周期写入 + 在线对话同时发生 | 同一事实可能被睡眠周期提取和在线对话同时写入，导致重复或冲突 |
| 热晋升标记 + 冷晋升执行 | 热晋升标记的缺失计数可能在冷晋升执行期间被修改 |
| 冷却系数更新 | 睡眠周期更新冷却系数时，检索可能读到不一致的中间状态 |

初步方向：写操作加行级锁，读操作不加锁（允许脏读，记忆系统对短暂不一致容忍度高）。睡眠周期和在线对话通过队列串行化对同一用户的操作。

### 9.3 监控告警

| 指标 | 说明 |
|:----|:-----|
| 检索延迟 | 各层检索延迟 P50/P95/P99 |
| 召回率 | 用户显式反馈（追问/纠正）的比率作为代理指标 |
| 失败率 | LLM 调用失败、FTS5 异常等 |
| 冷却分布 | 各热度区间的事实数量分布，监控冷却系统是否正常 |
| 睡眠周期耗时 | 各 Phase 耗时，异常增长告警 |

### 9.4 渐进激活降级体验

| 层 | 未激活时返回 |
|:--|:------------|
| L0 | 始终可用 |
| L1 | 始终可用 |
| L2 | 仅返回 L0+L1 结果，不报错 |
| L3 | 仅返回 L0+L1+L2 结果 |
| L4 | 仅返回 L0+L1+L2+L3 结果 |
| L5 | 仅返回 L0+L1+L2+L3+L4 结果 |

核心原则：**上层不可用时静默降级，不报错、不告知用户"该层未激活"**。FusionEngine 自动忽略缺失层。

### 9.5 人格模型版本管理与回滚

```
快照时机：每次 L5 更新前自动快照
快照内容：人格向量 + GMM 参数 + 心理探针状态（不可从原始数据重建的增量部分）
保留策略：保留最近 10 个版本，超出自动淘汰最旧版本
回滚行为：回滚后标记被跳过的版本为 rolled_over，防止自动恢复
```

| 场景 | 方案方向 |
|:----|:--------|
| 恶意数据污染 | 每次 L5 更新前自动快照，保留最近 10 个版本，支持按时间点回滚 |
| 异常漂移检测 | 人格模型变化幅度超过阈值时自动告警并暂停更新 |
| 版本对比 | 支持对比两个时间点的人格模型差异，辅助诊断 |

### 9.6 安全与隐私

| 风险 | 防护方向 |
|:----|:--------|
| prompt injection 污染记忆 | 提取阶段的输入消毒 + 写入前的异常模式检测 |
| 跨人记忆泄露 | 以人为中心的隔离模型（已有），确保不同用户的事实不混淆 |
| 敏感信息持久化 | 可选配置：过滤包含密码/密钥/身份证号等模式的事实
