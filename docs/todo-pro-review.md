## 一、情感维度检索设计

情感维度在架构文档中设计完整（三表结构），但检索文档几乎忽略。需讨论：
- 情感 embedding 检索（找到情感状态最相似的记忆）
- 情感轨迹匹配（找到情感转变模式类似的时期）
- 与心理探针检索共享基础设施的可能性

## 二、设计缺陷与风险

| # | 问题 | 严重度 | 说明 |
|:-:|:----|:----:|:----|
| 1 | LLM 成本被系统性低估 | 🔴 | 多个环节依赖 LLM，无整体成本估算 |
| 2 | 心理探针生成成本 | 🔴 | 每次 query 多一次 LLM 调用，chat 场景不可接受 |
| 3 | 符号规则引擎召回率 | 🔴 | 依赖非强制填充的结构化字段，实际覆盖率可能很低 |
| 4 | 反差检索冷启动 | 🟡 | Phase 1 每次 prediction/contradiction 都查空表 |
| 5 | L4 动态细节 LLM 成本失控 | 🟡 | 每次 narrative/persona/causal query 都调用 LLM |
| 6 | MMR 计算成本 | 🟡 | 30 候选需 435 次相似度计算 |
| 7 | 冷却系数乘性叠加 | 🟢 | 乘法的物理含义不清晰 |

## 三、创新建议

| # | 建议 | 价值 | 说明 |
|:-:|:----|:---:|:----|
| 1 | **闪回检索** | 🔥🔥🔥 | FTS5 扫描冷区关键词，临时加热到温区——低成本高价值 |
| 2 | **记忆蒸馏** | 🔥🔥🔥 | 主题冷数据超阈值时生成蒸馏摘要，降低原始数据检索优先级 |
| 3 | **自适应层权重** | 🔥🔥 | Phase 1 引入 LinUCB Bandit，根据隐式反馈自动调权 |
| 4 | **检索结果可解释性** | 🔥🔥 | 每个结果带 `explanation` 字段，说明检索路径 |
| 5 | **情感维度独立检索路径** | 🔥🔥 | 情感 embedding 检索 + 情感轨迹匹配 |
| 6 | **多视角叙事主干** | 🟢 | 职业/情感/成长等多视角 |
| 7 | **跨人记忆共鸣检索** | 🟢 | 相似人格的用户行为参考（需隐私保护） |

## 四、缺失环节

| # | 缺失 | 说明 |
|:-:|:----|:----|
| 1 | LLM 成本估算 | 无法判断经济可行性 |
| 2 | 测试策略 | 没有标注数据集、回归测试、评估指标 |
| 3 | 并发控制 | 睡眠周期和在线对话可能同时写入 |
| 4 | 监控告警 | 延迟、召回率、失败率 |
| 5 | 渐进激活降级体验 | 未激活层返回什么给用户 |
| 6 | 人格模型版本管理与回滚 | 被恶意数据污染时如何恢复 |
| 7 | 安全与隐私 | prompt injection 污染记忆的防护 |
