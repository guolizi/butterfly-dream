## 一、当前设计的问题

```
当前 emotion_states:
  emotion_label (开心/难过/焦虑...)
  intensity (0.0~1.0)

问题 1: 单一标签太粗糙
  "开心"和"兴奋"都是高愉悦，但唤醒度不同
  "平静"和"无聊"都是低唤醒，但愉悦度不同
  单标签+强度无法区分这些

问题 2: 没有参与冷却
  情感数据独立于遗忘机制
  长期积累 → 无限增长

问题 3: 情感来源单一
  只关联到触发事实 (context_fact_id)
  没有考虑多维度提取时情感也来自 L0→L1 晋升
```

## 二、VAD 三维模型

```
VAD 模型：
  Valence（愉悦度）  -1.0 ~ 1.0  愉快 ↔ 不愉快
  Arousal（唤醒度）   0.0 ~ 1.0  激动 ↔ 平静
  Dominance（支配度） 0.0 ~ 1.0  掌控 ↔ 无力

常见情感在 VAD 空间中的位置：

情感        Valence  Arousal  Dominance
─────────────────────────────────────
开心        +0.8     0.7      0.7
兴奋        +0.7     0.9      0.6
平静        +0.5     0.2      0.5
焦虑        -0.6     0.8      0.3
悲伤        -0.7     0.3      0.3
愤怒        -0.5     0.9      0.6
惊讶         0.0     0.8      0.4
无聊        -0.4     0.2      0.4
自豪        +0.7     0.6      0.8
羞愧        -0.5     0.4      0.2
```

### VAD 的好处

```
1. 更丰富的情感表达
   单标签+强度: "开心 0.8"
   VAD: valence=+0.8, arousal=0.7, dominance=0.7
   → 可以区分"兴奋的开心"和"平静的开心"

2. 情感轨迹更精确
   单标签: "开心 → 焦虑"（跳跃，中间状态丢失）
   VAD: (0.8,0.7,0.7) → (0.5,0.6,0.5) → (0.0,0.7,0.4) → (-0.6,0.8,0.3)
   → 可以看到情感在 VAD 空间中的连续变化路径

3. 情感模式更丰富
   单标签: "她压力大时会画画"
   VAD: "当 valence 下降 + arousal 上升时，她倾向于做高支配度活动"
   → 模式发现可以基于 VAD 空间中的区域，而非固定标签

4. 跨文化通用
   情感标签有文化差异（中文的"郁闷"没有精确英文对应）
   VAD 是跨文化的连续空间
```

## 三、更新后的数据结构

```
emotion_states（情感状态节点）:
  state_id, person, timestamp,
  valence, arousal, dominance,     -- VAD 三维核心
  emotion_label,                   -- 可选，方便人类阅读
  intensity (从 VAD 综合计算),      -- 派生字段
  context_fact_id,                 -- 关联到触发该情感的事实
  source (llm_extraction / l0_promotion / inferred),
  notes

emotion_transitions（情感转变）:
  transition_id, person,
  from_state_id, to_state_id,
  transition_type (正向突破/负向冲击/累积升华/韧性恢复/...),
  vad_delta (valence_change, arousal_change, dominance_change),
  trigger_fact_ids,
  pattern_id (可选)

emotion_patterns（情感模式）:
  pattern_id, person, description,
  vad_region (在 VAD 空间中的区域描述),
  confidence, source_transition_ids,
  created_at, updated_at
```

## 四、情感维度的冷却设计

```
情感维度参与冷热分级，但有自己的冷却规则：

emotion_states:
  ┌──────────────┬──────────────────┬──────────────────┐
  │ 冷却依据      │ 加速条件          │ 减速条件          │
  ├──────────────┼──────────────────┼──────────────────┤
  │ 时间衰减为主  │ 关联事实冷却      │ 被 L4 标记为      │
  │              │ 低频人物          │ 叙事关键情感节点   │
  └──────────────┴──────────────────┴──────────────────┘

emotion_transitions:
  ┌──────────────┬──────────────────┬──────────────────┐
  │ 冷却依据      │ 加速条件          │ 减速条件          │
  ├──────────────┼──────────────────┼──────────────────┤
  │ 跟随源状态    │ 源状态冷却        │ 被 L3 标记为      │
  │              │                  │ 情感模式的一部分   │
  └──────────────┴──────────────────┴──────────────────┘

emotion_patterns:
  ┌──────────────┬──────────────────┬──────────────────┐
  │ 冷却依据      │ 加速条件          │ 减速条件          │
  ├──────────────┼──────────────────┼──────────────────┤
  │ 重要性为主    │ 低频/已被替代     │ 高频出现          │
  │              │ 低 confidence    │ 高 confidence     │
  └──────────────┴──────────────────┴──────────────────┘

加热规则：
  - 被检索命中 → 热度 +1 级
  - 被 L4 标记为叙事关键情感节点 → 永久保持温以上
  - 被 L5 标记为人格特质相关情感 → 永久保持温以上
```

## 五、情感维度与各层的关系

```
L0→L1 晋升（多维度提取）：
  → 情感维度输出 → 写入 emotion_states

L1 事件记录池：
  → 事件触发情感 → context_fact_id 关联
  ← 情感状态为事件提供情感上下文

L2 关系层：
  → 时间链关联情感转变
  → 因果链解释情感转变的原因
  ← 情感轨迹为因果链提供情感信号

L3 抽象层：
  → 情绪转折检测（实时触发抽象管道）
  → 从 emotion_transitions 归纳 emotion_patterns
  ← 情感模式为行为预测提供输入

L4 叙事层：
  → 情感轨迹是故事线的情感弧线
  ← 叙事关键情感节点 → 情感冷却减速

L5 灵魂层：
  → 情感模式是人格模型的一部分（情绪调节模式）
  ← 人格特质相关情感 → 情感冷却减速

遗忘机制：
  → 情感数据参与冷热分级
  ← 各层冷却系数叠加影响情感热度
```

## 六、初期实现建议

```
初期（emotion_events 一表）：
  emotion_events:
    event_id, person, timestamp,
    valence, arousal, dominance,
    emotion_label,
    context_fact_id,
    source

  查询时动态推导：
    transitions = 按时间排序相邻 event 的 VAD 变化
    patterns = 聚类相似 VAD 变化路径

  冷却：
    简单时间衰减（按 timestamp 降权）
    不涉及各层冷却系数叠加

后期（数据量足够后物化三表）：
  emotion_states（从 emotion_events 迁移）
  emotion_transitions（物化推导结果）
  emotion_patterns（物化聚类结果）

  冷却：
    各层冷却系数叠加
    叙事关键/人格特质标记 → 永久保温
```
